# 브라우저에서 보기 (설치 없이)

방법이 두 가지입니다. **무엇이 필요한지로 고르세요.**

| | 데모 한 파일 | 브라우저 모드 |
|---|---|---|
| 필요한 것 | 브라우저 | 서버 두 개 + SSH 터널 |
| 데이터 | 페이지 안에 녹음된 것 | 실제 백엔드 |
| 실시간·다른 사람 | 없음 | 있음 |
| 용도 | **"어떻게 만들어지고 있나"** | 기능 검증 |

"어떻게 만들어지고 있나"를 보려는 것이라면 [데모 한 파일](#데모-한-파일)로 가세요.
실제로 동작하는지 확인해야 한다면 [브라우저 모드](#브라우저-모드)입니다.

데스크톱 앱을 빌드하려면 Rust + MSVC 빌드 도구(수 GB, 첫 빌드 10~20분)가 필요합니다.
이 문서는 양쪽 모두 그것을 건너뜁니다.

---

## 데모 한 파일

```bash
make demo            # → desktop/demo.html (약 3MB, 파일 하나)
```

이 파일만 있으면 됩니다. 열면 앱이 뜹니다 — 서버도, 터널도, 네트워크 요청도
**하나도** 없습니다 (검증 스크립트가 모든 외부 요청을 차단한 상태로 확인합니다).
메일로 보내도, 사내 위키에 올려도, 정적 호스팅에 올려도 그대로 동작합니다.

### 어떻게 동작하나

브라우저 모드의 어댑터를 그대로 쓰고, 유일한 HTTP 병목인 `request()` 한 곳만
메모리로 돌립니다.

```
데모:  UI ─→ api ─→ web.ts request() ─→ demo/index.ts ─→ 녹음된 응답 + 메모리
```

그 위의 모든 것 — 어댑터, 아웃박스, 스토어, 컴포넌트 — 이 실제 브라우저 모드와
**같은 코드**입니다. 별도로 만든 목업이 아니라 제품에 데이터 출처만 바꿔 끼운
것이라서, 여기서 본 화면은 실제 화면입니다.

`src/lib/demo/fixture.json` 은 **실행 중인 API 의 실제 응답을 녹음한 것**입니다.
손으로 쓴 픽스처는 흉내내는 API 와 어긋나고, 그러면 서버가 절대 돌려주지 않는
모양을 데모가 그리게 됩니다. 고칠 때는 편집하지 말고 다시 녹음하세요:

```bash
make seed && make dev      # 창 1
make demo-fixture          # 창 2: src/lib/demo/fixture.json 갱신
make demo
```

### 데모에서 되는 것 / 안 되는 것

**됩니다**: 채널 전환 · 전사록 · 스레드 · 메시지 보내기·수정·삭제 · 반응 ·
멘션 · ⌘K 통합 검색 · 채널 만들기 · 에이전트 패널(스크립트 프로바이더) ·
반응형 레이아웃 전부.

**안 됩니다** (각각 실제 오류 화면이 뜹니다 — 조용히 빠지지 않습니다):

- **실시간**: 소켓이 없습니다. 타이핑 표시, 프레즌스 갱신, 다른 사람 메시지가
  실시간으로 도착하는 것.
- **파일 업로드**: 받아줄 곳이 없습니다.
- **미니앱 패널**: 앱은 별도 오리진의 iframe 이 필요합니다.
- **실제 모델 응답**: 에이전트는 대신 자기가 왜 안 되는지 설명합니다.
- **저장**: 새로 고치면 처음부터입니다. 보낸 메시지도 사라집니다.

아무 비밀번호나 넣으면 들어갑니다. 지킬 것이 없습니다 — 데이터셋 전체가 이미
내려받은 페이지 안에 있습니다.

## 브라우저 모드

### 어떻게 동작하는지

UI 는 셸(Tauri)과 `api` · `events` 두 객체로만 이야기합니다
(`desktop/src/lib/ipc.ts`). 브라우저에는 그 셸이 없으므로, 같은 계약을
HTTP + WebSocket 으로 구현한 어댑터(`desktop/src/lib/web.ts`)가 대신 들어갑니다.
어느 쪽이 쓰일지는 실행 시점에 한 줄로 갈립니다.

```
데스크톱:  UI ─→ api ─→ Tauri IPC ─→ Rust 코어 ─→ HTTP/WS ─→ 백엔드
브라우저:  UI ─→ api ─→ fetch/WebSocket ───────────────────→ 백엔드
```

Vite 개발 서버가 `/api` 를 백엔드로 프록시하므로 페이지와 API 가 같은 오리진입니다.
CORS 설정도, 두 번째 터널도 필요 없습니다 — **포트 하나(1420)면 끝입니다.**

---

### 서버에서 (EC2)

```bash
make seed          # 최초 1회: DB + 시드 데이터
make dev           # 창 1: 백엔드 (127.0.0.1:8000)
make ui            # 창 2: 브라우저 모드 (127.0.0.1:1420)
```

둘 다 루프백에만 바인딩합니다. **SSH 터널은 서버 안에서 접속하는 것이라 이대로 됩니다** —
앱이 인터넷에 노출되지 않습니다.

LAN 주소로 직접 붙어야 할 때만 `make web` 을 쓰세요 (`0.0.0.0` 에 바인딩합니다).

### 윈도우에서

윈도우 10/11 에는 OpenSSH 가 기본 포함이라 **설치할 것이 없습니다.**
PowerShell 에서:

```powershell
ssh -i C:\path\to\your-key.pem -L 1420:127.0.0.1:1420 ec2-user@<서버주소>
```

이 창을 열어둔 채로 브라우저에서 **http://localhost:1420** 을 엽니다.

로그인: `alice@example.com` / `llack-dev-password`

> Session Manager 로 접속한다면:
> `aws ssm start-session --target <인스턴스ID> --document-name AWS-StartPortForwardingSession --parameters '{"portNumber":["1420"],"localPortNumber":["1420"]}'`

#### 예제 미니앱까지 보려면

앱 패널은 앱의 실제 웹페이지를 불러옵니다. 서버에서 `make example-app` 을 띄우고,
터널에 포트를 하나 더 얹으세요.

```powershell
ssh -i C:\path\to\your-key.pem -L 1420:127.0.0.1:1420 -L 5180:127.0.0.1:5180 ec2-user@<서버주소>
```

## 브라우저 모드에서 빠지는 것

어댑터가 흉내내지 않고 비워둔 것들입니다. 탭이 줄 수 없는 것이라서,
**데스크톱 앱에서만 확인할 수 있습니다.**

| 빠지는 것 | 데스크톱에서는 | 브라우저에서는 |
| --- | --- | --- |
| 로컬 캐시 | SQLite 에서 즉시 그리고 갱신 | 매번 네트워크 — 체감이 조금 느립니다 |
| 발신 대기열 | SQLite 에 남아 재시작 후에도 전송 | 메모리에만 — 새로 고치면 사라집니다 |
| 토큰 저장 | 윈도우 자격 증명 관리자 | `localStorage` — 개발용이며 운영 방식이 아닙니다 |
| OS 알림 · 트레이 배지 | 있음 | 없음 (사이드바 배지로 확인) |
| 딥링크 `llack://` | 설치된 앱에 등록 | 없음 |
| 파일 첨부 | 네이티브 파일 창 | 브라우저 파일 선택창 (동작은 같음) |

오프라인 전송(백엔드를 끄고 보내면 대기 → 켜면 전송)은 브라우저에서도 동작하지만,
탭을 새로 고치면 대기 중인 메시지가 사라집니다.

## 문제가 생기면

### 페이지가 열리지만 로그인이 안 됨

백엔드가 안 떠 있습니다. 서버에서 `make dev` 를 확인하세요.
`curl -s localhost:8000/api/v1/auth/config` 가 JSON 을 주면 정상입니다.

### `Blocked request. This host (...) is not allowed.`

Vite 가 모르는 호스트명을 막은 것입니다. 터널로 `localhost` 나 IP 로 접속하면
나지 않습니다. DNS 이름으로 붙어야 한다면:

```bash
LLACK_WEB_ALLOWED_HOSTS=llack.internal.example.com make web
```

### 터널은 붙었는데 페이지가 안 열림

터널의 목적지와 서버가 바인딩한 주소가 어긋난 경우입니다. `-L 1420:127.0.0.1:1420`
(목적지가 `127.0.0.1`)과 `make ui` 를 함께 쓰세요. 서버에서
`curl -s -o /dev/null -w '%{http_code}' localhost:1420` 이 200 이면 서버는 정상입니다.

### 백엔드를 다른 포트에서 돌리는 경우

```bash
LLACK_BACKEND_URL=http://127.0.0.1:8010 make web
```

### 세션이 이상해졌을 때

브라우저 콘솔에서 `localStorage.removeItem('llack.web.session')` 후 새로 고치면
로그인 화면으로 돌아갑니다.

---

## 알아두실 것

- 이 모드는 **개발·리뷰용**입니다. Vite 개발 서버와 `localStorage` 토큰은 운영
  구성이 아닙니다. 실제 배포에서는 빌드된 정적 파일을 리버스 프록시 뒤에서 서빙하고,
  토큰은 셸(또는 HttpOnly 쿠키)이 들고 있어야 합니다.
- 터널을 쓰면 앱이 인터넷에 열리지 않습니다. 보안 그룹에 1420 을 여는 것보다
  이 방법을 권합니다.
- 데스크톱 앱까지 보고 싶어지면 [WINDOWS.md](WINDOWS.md) 의 2단계로 가세요.
