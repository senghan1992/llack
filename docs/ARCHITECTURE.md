## 왜 Rust 코어를 분리했는가

`desktop/core` 는 Tauri 에 의존하지 않는 독립 크레이트입니다. 이유가 두 가지 있습니다.

1. **테스트 가능성.** 토큰 갱신, 오프라인 큐, 이벤트 갭 감지, 캐시 일관성처럼
   버그가 실제로 나는 곳이 전부 여기 있습니다. GUI 라이브러리 없이 `cargo test` 로
   50개 테스트가 돕니다 — CI 컨테이너에서도, webkit2gtk 가 없는 머신에서도.
2. **재사용.** 같은 코어로 CLI, 서버 사이드 봇, 나중에 모바일 셸을 붙일 수 있습니다.

`src-tauri` 는 이 코어를 창·트레이·알림에 연결하는 어댑터일 뿐입니다.

## 데이터 모델

핵심 결정 세 가지입니다.

### 1. 모든 행의 기본키는 ULID

26자 Crockford base32, 앞 48비트가 밀리초 타임스탬프입니다. 결과적으로:

- `ORDER BY id` 가 곧 시간순입니다. 메시지 정렬에 별도 컬럼이 필요 없고
  `(channel_id, id)` 인덱스 하나로 채널 히스토리 쿼리가 끝납니다.
- 커서 페이지네이션이 `WHERE id < :cursor` 입니다. OFFSET 이 없어서
  새 메시지가 도착해도 페이지가 밀리지 않습니다.
- 클라이언트가 조율 없이 ID 를 미리 만들 수 있습니다. 낙관적 UI 의 전제조건입니다.

**주의해서 구현한 부분**: 같은 밀리초 안에서 순수 랜덤 ULID 는 생성 순서로 정렬되지
않습니다. 서버(`app/core/ids.py`)와 클라이언트(`core/src/ids.rs`) 양쪽 모두
**단조 증가 변형**을 씁니다 — 같은 밀리초면 랜덤 부분을 증가시킵니다.
빠르게 연타한 메시지가 뒤바뀌어 보이는 것을 막습니다.

### 2. 읽음 상태는 커서 하나

`channel_members.last_read_message_id` 가 ULID 이므로 "안 읽음"은 문자열 비교
`message.id > last_read_message_id` 입니다. 별도 조인 테이블이 없고,
커서는 절대 뒤로 가지 않습니다 (`services/channels.py:mark_read`).

`unread_count` / `mention_count` 는 비정규화해 둡니다. 사이드바가 메시지 테이블을
건드리지 않고 렌더되어야 하기 때문입니다. 팬아웃은 멤버당 한 문장이 아니라
**전체에 대해 UPDATE 두 문장**입니다 — 2,000명 채널에서 메시지마다 2,000개
쿼리를 날리지 않기 위해서입니다 (`services/messages.py:_bump_unread`).

### 3. DM 은 결정적 키로 식별

`channels.dm_key` = 참여자 ID 를 정렬해 `:` 로 이은 문자열. "X 와 대화 열기"가
검색이 아니라 멱등 upsert 가 됩니다. 누가 먼저 열었는지와 무관하게 같은 채널입니다.

### 테이블 요약

| 테이블 | 용도 | 눈여겨볼 점 |
| --- | --- | --- |
| `users` | 사람과 봇 | 봇도 사용자입니다 — 앱 메시지의 작성자 표시가 자연스러워집니다 |
| `sessions` | 기기별 로그인 | 리프레시 토큰은 **해시**로만 저장, 기기 단위 폐기 가능 |
| `workspaces` / `workspace_members` | 테넌트와 역할 | owner/admin/member/guest |
| `channels` / `channel_members` | 채널·DM 과 개인 설정 | 읽음 커서, 알림 수준, 음소거, 섹션 |
| `messages` | 메시지와 스레드 | `parent_id` 로 1단 스레드, `client_msg_id` 로 멱등성 |
| `reactions` / `message_attachments` | 반응·첨부 | |
| `files` | 워크스페이스 단위 파일 | 메시지와 분리 — 재업로드 없이 여러 채널 공유 |
| `apps` / `app_installations` | 미니앱과 설치 | 권한의 기준은 **설치** 레코드 |
| `app_tokens` / `app_storage_items` | 앱 토큰과 KV 저장소 | 앱이 자체 DB 없이 상태를 갖게 함 |

## 시간대 처리

SQLite 는 타임존을 저장하지 않아 `DateTime(timezone=True)` 를 읽으면 naive
datetime 이 돌아옵니다. Postgres 는 aware 를 돌려줍니다. 그대로 두면
`expires_at > utcnow()` 같은 비교가 **SQLite 에서만 터지고 Postgres 에서는
동작**하는 최악의 분기가 생깁니다.

그래서 모든 타임스탬프 컬럼이 `UTCDateTime` 커스텀 타입입니다
(`app/models/base.py`). 어느 백엔드든 파이썬 쪽에서는 항상 UTC-aware 입니다.

## 실시간 프로토콜

### 연결 수명

1. 클라이언트가 `/api/v1/ws?token=<access token>&workspace_id=<id>` 로 연결합니다.
   토큰이 쿼리 파라미터인 이유: 브라우저·웹뷰는 WebSocket 핸드셰이크에 헤더를
   붙일 수 없습니다. 액세스 토큰이 단기(기본 15분)라서 감수할 수 있는 트레이드오프입니다.
2. 서버가 인증 후 사용자의 토픽을 구독하고 `hello` 를 보냅니다
   (세션 ID, 워크스페이스 목록, 하트비트 간격, 서버 시각).
3. 클라이언트가 하트비트 주기로 `ping`, 서버가 `pong`. 2.5주기 동안 조용하면 끊습니다.
4. **모든 프레임에 단조 증가 `seq`.** 점프는 이벤트 유실을 뜻하므로 클라이언트가
   해당 채널을 다시 불러옵니다.

프레임은 **텍스트**로 보냅니다. 바이너리 프레임은 브라우저·웹뷰에서 Blob 으로
도착해 비동기로 읽어야 하는데, 텍스트는 그냥 문자열입니다.

### 토픽 팬아웃

이벤트는 세 종류의 토픽으로 흐릅니다.

```
ws:workspace:<id>   채널 생성, 앱 설치, 프레즌스
ws:channel:<id>     메시지, 반응, 타이핑
ws:user:<id>        본인 대상 (읽음 동기화, 알림)
```

허브는 이 프로세스가 들고 있는 소켓만 압니다. 워커가 여러 개면
`POST /messages` 를 처리한 워커가 만든 이벤트가 다른 워커의 소켓에 닿아야 하므로
**이벤트 버스**가 그 사이에 있습니다:

- `RedisEventBus` — Redis pub/sub. 프로덕션.
- `LocalEventBus` — 프로세스 내. 단일 워커에서 정확하고, 개발 환경에 인프라가 필요 없습니다.

`LLACK_REDIS_URL` 설정 여부로 자동 선택됩니다.

### 배압

연결마다 상한 있는 송신 큐(512)와 writer 태스크가 있습니다. 클라이언트가 큐를
못 비우면 **연결을 끊습니다**. 무한히 버퍼링하지 않습니다 — 재연결 후 따라잡기
페치가 서버 메모리를 갉아먹는 큐보다 싸기 때문입니다.

## 인증

- **액세스 토큰**: 단기 서명 JWT. DB 왕복 없이 검증합니다.
- **리프레시 토큰**: 불투명 랜덤 문자열, `sessions` 테이블에 **키드 해시**로 저장.
  JWT 리프레시 토큰으로는 못 하는 **기기 단위 폐기**가 가능해집니다.
- **회전**: 리프레시할 때마다 새 리프레시 토큰이 발급됩니다. 쓴 토큰을 다시 내면
  실패하므로, 토큰 탈취가 조용히 지속되지 않고 드러납니다.
- **단일 비행 갱신**: 401 을 동시에 받은 요청들이 각자 리프레시하면 회전 때문에
  첫 번째만 성공하고 나머지는 로그아웃됩니다. 클라이언트가 갱신을 뮤텍스로
  직렬화합니다 (`core/src/api.rs:refresh_access_token`).
- **타이밍**: 존재하지 않는 계정도 더미 해시로 검증해 없는 계정과 틀린 비밀번호가
  같은 시간을 쓰게 합니다.
- **비밀번호**: Argon2id.

리프레시 토큰은 데스크톱에서 **OS 키체인**에 들어갑니다 (macOS Keychain,
Windows Credential Manager, Linux Secret Service). 키체인을 못 쓰는 환경에서는
메모리로 강등됩니다 — 다음 실행에 다시 로그인해야 하지만, 앱이 아예 안 켜지는
것보다 낫습니다.

## 파일

2단계 업로드입니다.

1. `POST /workspaces/{id}/files` — 행을 선점하고 업로드 티켓을 받습니다.
2. 바이트 전송 — 로컬 백엔드는 `PUT /files/{id}/content`, S3 는 presigned URL 로 직행.

이렇게 나눈 이유: 클라이언트가 알려진 file_id 에 대해 진행률을 보여줄 수 있고,
재시도가 새 행을 만들지 않습니다. `is_ready` 가 false 인 파일은 메시지에 붙일 수 없습니다.

권한: 워크스페이스 멤버면 읽을 수 있지만, **파일이 채널에 공유된 이후에는
그 채널 중 하나의 멤버여야** 합니다. 그렇지 않으면 워크스페이스 멤버가 ID 만으로
비공개 채널의 첨부를 읽게 됩니다 (`api/v1/files.py:_authorise_read`).

## 검색

지금은 사용자가 속한 채널에 대한 `LIKE` 스캔입니다. 정확하고 추가 인프라가 필요
없습니다. Postgres 전문검색이나 외부 색인으로 바꿀 때 손댈 곳은
`services/messages.py:search_messages` 하나입니다.

## 오프라인 동작

```
사용자가 Enter →  ULID + client_msg_id 부여
              →  로컬 아웃박스(SQLite)에 저장
              →  전송 시도
                 ├─ 성공        → 아웃박스에서 제거, 서버 메시지로 대체
                 ├─ 네트워크 실패 → pending 유지, 재연결 시 배출
                 └─ 영구 실패    → failed 로 표시, 사용자가 재시도/삭제
```

배출은 재시도 가능한 실패에서 **멈춥니다**. 채널 안 메시지 순서를 지켜야 하므로
실패한 것을 건너뛰고 다음을 보내면 순서가 뒤바뜁니다 (`core/src/sync.rs:drain_outbox`).

## 데스크톱 빌드 요구사항

| 플랫폼 | 필요한 것 |
| --- | --- |
| macOS | Xcode Command Line Tools |
| Windows | MSVC C++ 빌드 도구 + WebView2 런타임 (윈도우 11 은 기본 포함) |
| Ubuntu/Debian | `libwebkit2gtk-4.1-dev libgtk-3-dev libsoup-3.0-dev librsvg2-dev libdbus-1-dev build-essential` |
| Fedora | `webkit2gtk4.1-devel gtk3-devel libsoup3-devel librsvg2-devel dbus-devel` |

리눅스에서 `libdbus-1-dev` 가 필요한 이유: 리프레시 토큰을 OS 비밀 저장소에 넣기 위해
`keyring` 크레이트를 쓰고, 리눅스에서는 그것이 Secret Service(D-Bus)로 연결됩니다.
윈도우는 Credential Manager, macOS 는 Keychain 을 쓰므로 추가 패키지가 없습니다.

아이콘은 `python3 scripts/generate_icons.py` 로 코드에서 생성합니다. 저장소에 아무도
재생성할 수 없는 바이너리 에셋을 두지 않기 위해서입니다. 실제 로고로 교체하려면
`cd desktop && npm run tauri icon <로고.png>` 를 쓰세요.

Amazon Linux 2023 에는 webkit2gtk 패키지가 없어 셸 링크가 불가합니다.
`llack-core` 는 어디서든 빌드·테스트됩니다.

## 배포

- API 는 uvicorn 멀티 워커로 실행하고 리버스 프록시 뒤에 둡니다.
  `--proxy-headers --forwarded-allow-ips <프록시 IP>` 를 붙이세요
  (`*` 는 개발용입니다 — 클라이언트가 IP 를 위조할 수 있습니다).
- 워커가 2개 이상이면 **Redis 가 필수**입니다. 없으면 워커 간에 이벤트가 안 갑니다.
- WebSocket 이 통과하도록 프록시에 업그레이드 헤더와 긴 idle timeout 을 설정하세요.
- `LLACK_SECRET_KEY` 를 바꾸면 모든 세션과 앱 토큰이 무효화됩니다 (키드 해시라서).
- 마이그레이션은 컨테이너 시작 시 `alembic upgrade head` 로 적용됩니다 (멱등).
