# 배포 — 팀에게 "이거 쓰세요"라고 말하기 전까지

단일 서버, 수십 명 규모의 사내 파일럿을 기준으로 합니다. 이 문서의 끝에서
당신은 HTTPS 주소 하나를 팀에 공유하고, 초대 링크로 사람을 들이게 됩니다.

## 무엇이 뜨나

`docker compose up` 하나로 다섯 컨테이너가 뜹니다:

```
브라우저 ── web (nginx: 정적 번들 + /api 프록시 + /ws 업그레이드)
                 │
                 └── api (FastAPI, 4 워커, 부팅 시 마이그레이션)
                       ├── postgres  (데이터)
                       ├── redis     (워커 간 실시간 팬아웃 · 프레즌스)
                       └── minio     (파일 저장 — 실서비스는 실제 S3 권장)
```

웹과 API 가 **같은 오리진**입니다. CORS·쿠키·WebSocket 오리진 문제가
구성상 존재하지 않습니다 (개발의 vite 프록시와 같은 모양).

## 1. 시크릿 준비

```bash
cp .env.example .env
python3 -c "import secrets; print(secrets.token_urlsafe(48))"   # → LLACK_SECRET_KEY 에
```

`LLACK_SECRET_KEY` 없이 compose 는 시작을 거부하고, 개발 기본값이나 32자
미만이면 **API 가 부팅을 거부**합니다 (`validate_production_settings`).
이 키로 모든 토큰이 서명되므로, 유출되면 전부 재발급입니다.

## 2. 띄우기

```bash
docker compose up -d --build
docker compose logs -f api        # "startup" 로그와 마이그레이션 확인
```

기본 게시 포트는 80 입니다 (`LLACK_WEB_PUBLISH` 로 변경).

## 3. HTTPS

TLS 는 이 compose 앞에서 종료하세요 — 사내 표준 리버스 프록시(nginx,
Caddy, ALB 등)가 `https://llack.내회사.com` 을 `web:80` 으로 넘기면
됩니다. Caddy 예:

```
llack.example.com {
    reverse_proxy 127.0.0.1:80
}
```

브라우저 알림(Notification API)과 클립보드 API 는 HTTPS 에서만 동작하므로
이 단계는 장식이 아닙니다.

## 4. 첫 부팅: 첫 사람이 들어가는 법

프로덕션 기본값은 `LLACK_REQUIRE_INVITE=true` — 초대 없인 아무도 가입할 수
없습니다. 그런데 첫 관리자는 초대해 줄 사람이 없습니다. 순서:

1. **일시적으로 가입을 엽니다**: `.env` 에 `LLACK_REQUIRE_INVITE=false`,
   `docker compose up -d api`.
2. 접속해 **계정을 만들고 → 워크스페이스를 만듭니다** (빈 상태 화면의
   "워크스페이스 만들기" — 만든 사람이 소유자가 되고 #general/#random 이
   생깁니다).
3. **다시 잠급니다**: `LLACK_REQUIRE_INVITE=true` 로 되돌리고
   `docker compose up -d api`.
4. 이후 합류는 전부 초대로: 환경설정(사이드바 톱니) → **구성원 초대** →
   이메일 입력 → 링크 복사 → 전달. 받은 사람은 링크로 접속해 가입하면
   자동으로 워크스페이스에 들어옵니다.

## 5. 운영 루틴

- **메일(SMTP) 설정**: 워크스페이스 소유자가 앱 안에서 직접 잡습니다 —
  환경설정 → **메일 (SMTP)** 에 호스트·포트·계정·발신 주소를 넣고
  **테스트 메일**로 연결을 확인한 뒤 저장하세요. 저장한 비밀번호는 화면으로
  다시 내려오지 않고(`저장됨` 표시만), 서버에만 남습니다. 이 화면이 비어 있으면
  `.env` 의 `LLACK_SMTP_*` 를 폴백으로 씁니다. 둘 다 없으면 콘솔 로그로 떨어집니다.
- **비밀번호 분실**: 로그인 화면의 "비밀번호를 잊으셨나요?" — 가입 이메일로
  6자리 코드(15분 유효, 5회 시도 제한)가 갑니다. **SMTP 를 안 잡았으면 코드가
  서버 로그에 남으므로**(`docker compose logs api | grep mail.console`) 관리자가
  읽어 전달할 수 있습니다. 보조 수단으로 관리자 **임시 비밀번호 발급**(환경설정 →
  구성원 초대)도 그대로 있습니다.
- **비밀번호 변경(평시)**: 각자 환경설정 → 계정에서 언제든지.
- **초대 메일**: 메일 서버가 잡혀 있고 `LLACK_PUBLIC_WEB_URL`(예 `https://llack.내회사.com`)이
  있으면 초대 링크가 자동으로 메일로 갑니다(없으면 관리자 브라우저의 Origin 을 씀). 대기
  목록의 **다시 보내기**는 새 링크를 만들어 다시 보내고 옛 링크는 즉시 무효가 됩니다.
- **초대 회수**: 링크가 잘못 나갔으면 같은 화면의 대기 목록에서 **회수**.
- **방해 금지**: 각자 환경설정 → 알림 시간에서 매일 조용한 시간(요일 포함)과 일시 중지를
  정합니다. 그 동안 토스트·OS 알림이 멈추고 배지는 계속 셉니다. `@here` 는 지금 접속 중인
  사람만, `@channel` 은 전원을 부릅니다.
- **나중에 · 리마인더**: 저장한 메시지의 알림은 1분 작업자 `reminders_due` 가 보냅니다.
- **링크 카드**: 메시지의 첫 링크를 서버가 한 번 가져와(SSRF 가드, 128KB, 24시간 캐시)
  제목·설명·이미지를 붙입니다. `LLACK_UNFURL_ENABLED=false` 로 끕니다. 사내 주소(사설 IP)는
  가져오지 않으므로 카드가 붙지 않는 것이 정상입니다.
- **감사 로그**: 환경설정 → 감사 로그(관리자). 역할 변경·내보내기·초대 발급/회수·
  임시 비밀번호·채널 이름 변경/보관·앱 설치/제거·SMTP·보관 정책 변경이 행위자·IP·시각과
  함께 남습니다. `GET /workspaces/{id}/audit/export.csv` 로 최근 1만 건을 CSV(BOM, 엑셀 호환)로
  받을 수 있습니다. 애플리케이션 코드는 이 표를 수정하지 않습니다.
- **보관 정책**: 환경설정 → 보관 정책(관리자)에서 메시지·파일 보존 일수를 정합니다(비우면
  영구). 채널 설정에서 채널별로 메시지 보존 기간을 덮어쓸 수 있습니다. 매시간 작업자가 기한
  지난 메시지를 비우고(행은 남아 스레드 자리를 지킴) 파일을 스토리지에서 지웁니다 — 고정된
  메시지도 예외가 아닙니다. 로그 `retention.swept`.
- **첨부 바이러스 검사**: `.env` 에 `LLACK_CLAMAV_HOST`(clamd, INSTREAM/TCP) 를 넣으면 모든
  업로드가 백그라운드로 검사됩니다. 감염 파일은 격리(바이트 삭제·첨부 해제)되고 올린
  사람에게 알림이 가며 감사 로그 `file.quarantined` 가 남습니다. 비워두면 검사 없이
  `scan_status=skipped` 입니다.
- **메트릭**: `LLACK_METRICS_TOKEN` 을 두고 Prometheus 가 `GET /metrics`(Bearer) 를 긁게
  하세요. 요청 수/지연(라우트 템플릿별), WebSocket 연결 수, 메시지 수, 작업자 실행 수.
- **백그라운드 작업자**: API 프로세스 안에서 돕니다(별도 배포 없음). 안 읽음 재계산(6시간),
  보관 정책(1시간), 프레즌스 정리(1분). Redis 가 있으면 잡마다 리더 락으로 한 노드만
  실행합니다. `LLACK_RUN_WORKERS=false` 로 끌 수 있습니다.
- **동영상**: 다운로드가 `Range` 를 지원하고, `<video>` 태그용 10분짜리 미디어 토큰
  (`POST /files/{id}/media-token`)이 있어 녹화 파일을 앱 안에서 바로 재생·탐색합니다.
- **부하 테스트**: `backend/scripts/loadtest.py --api https://주소 --users 20 --messages 50`
  — 스테이징에서 p50/p95/오류율을 봅니다. 노트북 SQLite 숫자는 의미가 없습니다.
- **백업**: `postgres-data`, `minio-data` 볼륨 두 개가 상태의 전부입니다.
  `pg_dump` + 버킷 동기화를 cron 에 걸어두세요.
- **로그**: `docker compose logs api` — 요청당 한 줄(JSON), 요청 id 포함.

## 6. 알아두어야 할 한계 (정직하게)

- **레이트 리밋**은 Redis 가 있으면 노드 전체에서 하나의 버킷(Lua, 원자적)이고, 없으면
  워커별입니다. Redis 가 죽으면 인프로세스로 조용히 내려앉고 경고 로그를 한 번 남깁니다 —
  로그인이 막히는 것보다 한도가 잠시 느슨한 쪽을 택했습니다.
- **초대는 링크 전달**: 초대 메일 자동 발송은 아직 없습니다 (재설정 코드 메일은 있음).
- **검색**은 Postgres 에서 전문검색(`simple` 설정, GIN 인덱스, `ts_rank` 정렬)이고
  SQLite 에서는 LIKE 스캔입니다. 형태소 분석은 없으므로 한국어는 어절 단위로 맞습니다.
- **데스크톱 앱 배포는 별도**입니다 (macOS/Windows 에서 빌드, 자동 업데이트
  없음). 파일럿은 웹 모드로 시작하는 것을 권합니다 — 기능 차이는
  [WEB.md](WEB.md)와 PRODUCT.md 의 제약 절에 있습니다.
- 규모 한계와 교체 지점은 [ROADMAP.md](ROADMAP.md) "알려진 한계" 절.

## 검증

배포 후 이 세 가지가 지나가면 정상입니다:

1. `curl https://주소/health` → `{"status":"ok"}`
2. 로그인 → 채널에서 메시지 전송 → 두 번째 브라우저에서 1초 내 수신
3. 파일 업로드 → 이미지 미리보기 → ⌘K 로 파일 검색

개발 머신에서는 `make smoke-ui`(92검사)가 같은 것을 자동으로 확인합니다.
