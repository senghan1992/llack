# 로드맵

이 초안에 **없는 것**을 솔직하게 적고, 다음에 무엇을 할지 정리한 문서입니다.
지시하실 때 이 목록을 기준으로 골라주시면 됩니다.

## 지금 동작하는 것

- 이메일/비밀번호 인증, 기기별 세션, 토큰 회전, 기기 단위 폐기
- 워크스페이스, 역할(owner/admin/member/guest), 초대
- 공개·비공개 채널, 1:1 및 그룹 DM, 채널 찾아보기
- 채널 설정 UI: 이름·주제 수정, 구성원 추가/제거(관리자), 보관, 나가기
- 메시지: 마크다운, 멘션, 1단 스레드, 반응, 고정, 수정·삭제
- 파일: 2단계 업로드(로컬/S3), 첨부, 워크스페이스 파일 브라우저
- 읽음 상태, 안 읽음·멘션 카운터, 알림 수준, 음소거
- 실시간: WebSocket 게이트웨이, 타이핑, 프레즌스, seq 갭 감지, 재연결
- 미니앱: 매니페스트 등록, 설치, 스코프, 브릿지 API, 샌드박스 패널, KV 저장소, 봇 계정
- 링크 앱: URL 하나로 팀의 웹 도구를 도크에 추가 → 메인 패널 iframe.
  브릿지 토큰 발급이 구조적으로 불가(`has_panel`=false), 스코프 금지, http(s)만
- 통합 검색 (⌘K): 채널·사람·앱·메시지·파일 (파일은 Enter 로 바로 다운로드)
- 오프라인: 로컬 SQLite 캐시, 아웃박스, 멱등 재전송
- **에이전트 패널**: 세 번째 도킹 시트, 사용자가 연결하는 프로바이더(키는 OS 키체인),
  Rust 정책 게이트 + 액션별 승인 + 해시 체인 감사 로그, 채널 읽기·검색·게시 도구,
  `host.exec`/`host.read_file`/`host.write_file`, 아티팩트(핸들+프리뷰). 자세한 것과 **없는 것**은
  [AGENT.md](AGENT.md) 에 있습니다.

## 1순위 — 상용 배포 전에 반드시

| 항목 | 왜 필요한가 |
| --- | --- |
| **SSO (SAML / OIDC)** | 커스텀 인증으로 운영하는 동안의 잠금은 마련됨: `LLACK_REQUIRE_INVITE=true` 면 유효한 초대 토큰 없는 가입이 403 (기본값 false 는 dev 편의). SSO 자체는 사용자가 직접 구현 예정. |
| **레이트 리밋 (다중 노드)** | 로그인(이메일+IP)·가입(IP)·메시지(사용자)·검색(사용자)에 **인프로세스 토큰 버킷**이 있습니다 (`app/core/ratelimit.py`, 한도는 설정). 단일 워커에서 정확하고 워커 N개면 N배로 완화되므로, 다중 노드 배포 전에 같은 시그니처 뒤에 Redis 버킷을 붙여야 합니다. |
| **비밀번호 재설정 이메일** | 관리자 임시 비밀번호 발급은 있음(환경설정). 셀프서비스 재설정은 메일러가 생겨야 합니다. |
| **자동 업데이트** | 배포한 데스크톱 앱을 갱신할 수단이 없습니다. Tauri updater + 서명. |
| **감사 로그** | 관리자 행위(권한 변경, 앱 설치, 멤버 제거) 추적. 규정 대응에 필요합니다. |
| **첨부 바이러스 검사** | 사내에 파일이 오가는 순간 요구사항이 됩니다. |
| **보관 정책** | 채널별 메시지·파일 보존 기간과 삭제 작업자. |
| **부하 테스트** | 채널 규모별 팬아웃 비용을 실제로 측정해야 합니다. |

## 2순위 — 일상 사용성

- **알림 스케줄**: 업무 시간 외 방해 금지, 일시 중지
- **읽지 않음 모아보기 / 나중에 볼 항목**: Slack 의 "Later" 대응
- **이모지 피커**: 빠른 반응 4개를 넘어 임의 이모지
- **채널 둘러보기 사이드바 진입점**: 발견이 ⌘K 지식에 의존합니다
- **파일 브라우저 화면**: 백엔드 목록 API 는 있고 화면이 없습니다 (⌘K 검색만)
- **초대 이메일 자동 발송**: 지금은 링크를 관리자가 복사해 직접 전달합니다
- **메시지 저장·리마인더**
- **채널 섹션 UI**: 스키마와 API 는 있지만 사이드바 편집 UI 가 없습니다
- **링크 언펄**: 스키마의 `blocks` 를 쓰면 되지만 언펄러가 없습니다
- **동영상 인라인 미리보기**: 이미지는 인라인 미리보기 + 라이트박스가 있습니다
  (10MB 이하, 셸 경유 데이터 URL). 동영상은 아직 칩입니다
- **@here 와 @channel 구분**: 현재 동일하게 취급합니다

v1 은 한 줄기를 끝까지 만든 것이고, 아래는 전부 **이음매만 있는 상태**입니다. 각 항목이
왜 추가만으로 끝나는지는 [AGENT.md](AGENT.md) 에 적어뒀습니다.

| 항목 | 지금 상태 |
| --- | --- |
| **MCP 서버 등록** | 구독 서비스 연결. `ToolSource` 에 자리가 있고 등록 UI·핸드셰이크·자격증명 저장이 없습니다. 사용자가 요청한 방식이라 v2 의 1순위입니다. |
| **3등급 네이티브 다이얼로그** | 지금은 `host.exec` 도 인앱 카드입니다. JS 가 위조하거나 스크립트로 클릭할 수 없는 OS 다이얼로그로 올려야 합니다. |
| **REPL 도구 + 서브에이전트** | 아티팩트를 자르고 거를 수는 있지만 계산은 못 합니다. 저장소가 목적지이고 호출자가 없습니다. |
| **메모리 · 스킬** | 세션 간에 기억하는 것이 없습니다. |
| **화면·마우스 제어** | 스크린샷도 클릭도 없습니다. 정책에 2등급 자리만 비어 있습니다. |
| **두 번째 프로바이더** | `ProviderAdapter` 인터페이스에 구현이 하나입니다. |
| **감사 로그 열람 UI** | 검증 명령은 있고 화면이 없습니다. |

## 3순위 — 앱 플랫폼 완성

- **슬래시 커맨드 디스패치**: 매니페스트 선언은 저장되지만 라우팅되지 않습니다
- **이벤트 웹훅**: `event_subscriptions` 는 저장되지만 발송기가 없습니다
- **인터랙티브 블록**: 메시지 안 버튼·선택 UI
- **앱 심사 워크플로**: 사내 공용 앱 게시 승인
- **앱 홈 탭**: 채널과 무관한 앱 전용 화면
- **앱 개발자 콘솔**: 지금은 curl 로 등록합니다

## 4순위 — 규모와 운영

- **검색 엔진 교체**: 지금은 LIKE 스캔입니다. Postgres 전문검색 → 필요시 외부 색인.
  손댈 곳은 `services/messages.py:search_messages` 하나입니다.
- **메시지 파티셔닝**: 대량 워크스페이스에서 `messages` 를 시간 기준 파티션으로
- **읽음 카운터 정합성 작업자**: 지금도 `recompute_unread` 가 있지만 주기 실행이 없습니다
- **메트릭·트레이싱**: OpenTelemetry, Prometheus
- **다중 노드 프레즌스 정리**: 노드가 죽었을 때의 프레즌스 잔류 처리
- **파일 썸네일 생성**: `thumbnail_key` 컬럼은 있고 생성기가 없습니다

## 알려진 한계

의도적으로 남긴 것들입니다. 필요해지면 바꾸면 됩니다.

- **스레드는 1단**입니다. 답글의 답글은 같은 스레드에 들어갑니다 (Slack 과 동일).
- **검색은 LIKE 스캔**입니다. 수만 건까지는 문제없고, 그 이상에서 교체 지점이 명확합니다.
- **개발 기본값은 SQLite** 입니다. 프로덕션은 반드시 Postgres 를 쓰세요
  (동시 쓰기 처리량이 다릅니다).
- **Redis 없이 워커 2개 이상은 불가**합니다. 이벤트가 워커 간에 전달되지 않습니다.
  단일 워커로는 완전히 정확합니다.
- **`--forwarded-allow-ips *`** 가 개발 기본값입니다. 프로덕션에서는 프록시 IP 로
  좁혀야 합니다 — 그러지 않으면 클라이언트가 X-Forwarded-For 를 위조할 수 있습니다.
- **로컬 캐시는 암호화되지 않습니다.** 메시지 본문이 사용자 데이터 디렉터리의
  SQLite 에 평문으로 있습니다. 디스크 암호화를 전제하고 있습니다.
- **Tauri 셸은 이 환경에서 빌드되지 않습니다** (webkit2gtk 없음).
  macOS/Windows/Ubuntu 에서 빌드하세요.
