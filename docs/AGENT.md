# 에이전트 패널

Llack 안에서 동작하는 AI 어시스턴트입니다. 스레드·미니앱 패널과 같은 자리에 도킹하는
**세 번째 시트**이고, 별도 창도 별도 앱도 아닙니다.

이 문서는 **있는 것과 없는 것을 같은 무게로** 적습니다. 이 저장소의 다른 문서와 같은
방침입니다 — 없는 기능을 나중에 발견하는 것이 문서를 읽는 사람에게 가장 비싼 일이라서
그렇습니다.

---

## 무엇을 할 수 있나

| 도구 | 하는 일 | 승인 |
|---|---|---|
| `agent.context` | 지금 보고 있는 워크스페이스·채널이 무엇인지 | 없음 |
| `chat.read_channel` | 채널의 최근 메시지 | 없음, 단 **세션에 taint** |
| `chat.search` | 워크스페이스 메시지 검색 | 없음, 단 **세션에 taint** |
| `artifact.query` | 저장된 결과의 일부 (`head`/`tail`/`slice`/`grep`/`count`) | 없음 |
| `host.read_file` · `host.list_dir` | 파일 읽기 · 디렉터리 목록 | 세션 루트 안이면 없음, 밖이면 승인 |
| `host.write_file` | 파일 쓰기 (통째로 덮어씀, 상위 디렉터리는 있어야 함) | **항상 승인** — 루트 안에서도. 같은 경로는 세션 기억 가능, taint 후엔 매번 |
| `host.exec` | 프로그램 실행 | **매번 승인, 기억하지 않음** |
| `chat.post_message` | 나로서 메시지 게시 | **매번 승인, 기억하지 않음** |

`host.*` 는 데스크톱 앱에서만 노출됩니다. 브라우저 모드에서는 목록에서 아예 빠지므로
모델이 시도조차 하지 않습니다.

## 무엇을 할 수 없나 (v2)

v1 에서 이음매만 있던 것들은 대부분 채워졌습니다. 아래는 **v2 에서 실제로 되는 것**과
**아직 안 되는 것**을 나눠 적습니다. 안 되는 것은 여전히 정직하게 둡니다.

이제 됩니다.

- **MCP 서버 등록** — 등록 UI·핸드셰이크·자격증명 저장이 모두 있습니다. 토큰은
  키체인에만 두고, 서버가 준 도구는 `ToolSource::Mcp` 로 카탈로그에 합류합니다.
- **화면·마우스 제어** — `host.screenshot`(2등급)·`host.click`·`host.type_text`(3등급)가
  있습니다. 단 **기본 빌드에는 없습니다**: `screen-control` 카고 피처를 켜야 컴파일되고,
  끄면 도구가 카탈로그에 아예 나타나지 않습니다. 폭발 반경이 커서 배포 시 의도적으로
  선택하게 두었습니다.
- **계산 · 서브에이전트** — 아티팩트를 rhai 로 평가(`artifact.eval`)하고, `agent.delegate`
  로 서브에이전트에게 일을 맡긴 뒤 답만 아티팩트 핸들로 돌려받습니다.
- **메모리 · 스킬** — 세션을 넘어 기억합니다. `memory.save`/`search`/`forget` 는
  사용자별 노트를 SQLite 에 두고(신뢰할 수 없는 내용을 읽은 뒤의 저장은 매번 승인),
  스킬은 `agent-skills/{이름}.md` 파일로 두어 `skill.list`/`read` 로 불러옵니다.
- **두 번째 프로바이더** — `Provider`/`ProviderId` 로 일반화되어 Anthropic 과 OpenAI 를
  같은 바이트 프록시로 씁니다. 키는 프로바이더별로 키체인에만 있습니다.

아직 안 됩니다. (이음매만 있습니다.)

- **멘션 실행** — 채널에서 `@에이전트` 를 불러도 반응하지 않습니다. 에이전트는
  **내가 패널에서 지시할 때만** 움직입니다.
- **예약 실행** — cron 이 없습니다. 로그인 트리거로 스스로 깨어나는 경로도 없습니다.

이 둘을 미룬 이유는 같습니다. 사람이 시작하지 않은 턴은 승인 카드를 볼 사람이 그
순간에 없을 수 있고, 그러면 3등급 게이트의 의미가 약해집니다. 무인 실행은 게이트를
다시 설계한 뒤에 붙입니다.

- **백엔드 변경** — 없습니다. 채팅 도구는 기존 `ApiClient` 를 그대로 씁니다.

## 왜 루프는 TypeScript 이고 게이트는 Rust 인가

```
webview (TS)                          Rust (llack-core + src-tauri)
@anthropic-ai/sdk toolRunner
  │  fetch: ipcFetch ────────────►  agent_provider_request
  │                                   · api.anthropic.com 만 (상수, 설정 아님)
  │  ◄──────────────── 바이트만       · 키체인에서 x-api-key 주입
  │
  └  tool_use ────────────────────►  agent_tool_call
                                      · policy::classify()   ← 경계
                                      · audit(intent) → 승인 → 실행 → audit(outcome)
```

세 관심사를 따로 놓으면 답이 하나로 정해집니다.

| 관심사 | 위치 | 이유 |
|---|---|---|
| 프로바이더 키 | **Rust / OS 키체인** | 같은 웹뷰가 신뢰할 수 없는 마크다운을 렌더합니다. 협상 불가. |
| 정책 · 승인 · 감사 | **Rust** | 웹뷰가 넘을 수 없는 곳에 있어야 의미가 있습니다. |
| 대화 루프 | **TS (공식 SDK)** | 위 둘이 지켜지면 보안과 무관합니다. 유지보수가 가장 싼 곳에 둡니다. |

루프를 Rust 에 두지 않는 이유는 보안이 아니라 비용입니다. Rust 에는 공식 Anthropic SDK 가
없어서 SSE 프레이밍, `input_json_delta` 부분 JSON 누적, 재시도 분류, `thinking` /
`output_config` / `stop_reason` 같은 API 변화를 영구히 직접 떠안게 됩니다. 그리고 키가
웹뷰에 없는 것은 어느 쪽이든 같습니다.

### 바이트 프록시가 실제로 사는 것

정직하게: 웹뷰가 XSS 되면 앱이 열려 있는 동안 키를 **쓸** 수는 있습니다. **읽을** 수는
없고, 저장할 수도 없고, 창을 닫은 뒤에는 쓸 수도 없습니다. `localStorage` 에 있는 키는
한 번 유출되면 영구히 쓰이므로, 이것은 훨씬 작은 상금입니다. 그 이상을 주장하지 않습니다.

## 프로바이더와 모델

연결은 **환경설정**(사이드바 하단 톱니)에서 합니다. 패널은 대화하는 자리이고,
설정은 한 번 하는 일이라 분리했습니다.

- **연결**: API 키를 입력하면 Rust 가 `GET /v1/models/{model}` 로 검증한 뒤
  OS 키체인에 저장합니다 (`agent_provider_connect`). 키는 웹뷰로 되돌아오지 않습니다.
- **모델 선택**: 연결되면 설정 화면이 **계정의 `/v1/models` 목록**을 바이트 프록시로
  가져와 보여줍니다. 구독이 쓸 수 있는 모델이 곧 선택지입니다 — 이 빌드에 하드코딩된
  목록이 아니라서, 계정에 모델이 추가되면 앱 업데이트 없이 나타납니다.
- **모델 전환**: `agent_provider_set_model` 은 키 없이 모델만 바꿉니다. 엔진은
  키가 키체인에 있을 때만 받아들이고, 모델 id 를 URL 에 들어갈 수 없는 문자
  기준으로 다시 검사합니다 (IPC 표면이므로 목록에서 왔다는 가정을 믿지 않습니다).
- 브라우저 모드에는 키체인이 없으므로 연결·전환 모두 거부되고, 스크립트 가짜
  프로바이더가 대신 섭니다.

## 승인

| 등급 | 예 | 전달 |
|---|---|---|
| 0 자동 | `agent.context`, 세션 루트 안 읽기 | 없음 |
| 1 자동 + taint | `chat.read_channel`, `chat.search` | 없음, taint 만 |
| 2 승인 (세션 기억 가능) | 루트 밖 읽기 · 파일 쓰기 (루트 안이라도) | 인앱 카드 |
| 3 매번 승인 (기억 안 함) | `host.exec`, `chat.post_message`, `host.click`/`type_text`, MCP | 네이티브 OS 다이얼로그 (끄면 인앱 카드) |
| 4 승인으로도 거부 | 아래 하드 경계 | — |

### taint — 이 설계에서 레버리지가 가장 큰 규칙

채널 내용이 모델 컨텍스트에 **처음 들어온 순간** 세션에 taint 플래그가 섭니다. 이후:

- 2등급이 3등급으로 올라갑니다.
- 세션 지속 allowlist 가 **무시**됩니다.
- 패널 헤더에 "채널 읽음" 칩이 나타납니다.

"에이전트가 채널을 읽는 행위" 자체가 게이트를 조이게 만드는 것입니다. 프롬프트 인젝션의
유입구가 정확히 거기이기 때문입니다. taint 는 세션 안에서 **절대 해제되지 않습니다**.

### 승인 카드는 Rust 가 계산한 사실만 렌더합니다

리터럴 argv(한 줄에 인수 하나), 해석된 절대 경로, 위험 등급, taint 여부. 모델이 쓴 설명은
접힌 채 "모델 설명 — 신뢰하지 마세요" 라벨을 달고 버튼과 떨어진 자리에 놓입니다.
에이전트가 읽은 채널 메시지를 쓸 수 있는 사람은 그 설명도 쓸 수 있고, **허용 버튼 옆의
정당화 문구가 바로 공격면**입니다.

두 버튼은 같은 무게입니다. 어느 쪽도 채워지지 않고, 마운트 시 어느 쪽에도 포커스가
가지 않고, DOM 순서상 거부가 먼저입니다. Esc 는 거부입니다.

### argv 전용 실행

`host.exec` 는 `argv: Vec<String>` 만 받습니다. 커맨드 문자열도 `sh -c` 도 없으므로
메타문자·파이프·리다이렉트 주입이 **구조적으로** 불가능합니다. 인터프리터
(`sh bash zsh python* node deno ruby perl osascript powershell cmd env xargs make cargo npm npx`)는
`Grain::Once` 로만 승인되고 **영구 등록 자체가 금지**입니다 — 모든 allowlist 의 우회로라서
그렇습니다. `sudo`/`doas`/`pkexec`/`su`/`runas` 는 거부합니다.

### 하드 경계 (4등급)

정규화된 경로에 대해 판정하고, open 후 다시 확인합니다.

- **Llack 자신의 상태**: `agent-audit/**`, `agent.sqlite3`, `cache.sqlite3*`, 키체인
- **호스트 자격증명**: `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, `~/.docker`,
  `~/.config/gcloud`, `~/.config/gh`, `~/.password-store`, `Library/Keychains`, 브라우저 로그인 DB
- **이 저장소의 비밀**: `**/.env*`(단 `.env.example` 제외), `*.pem`, `*.db`, `*.sqlite3`
- **자기 권한 상승 표면** (쓰기): `capabilities/*.json`, `tauri.conf.json`, `.git/hooks/**`,
  `Makefile`, `package.json`, `.github/workflows/**`
- **영속화 표면** (쓰기): `~/.bashrc`, `~/Library/LaunchAgents/**`, crontab, Run 키
- **커널 인터페이스**: `/proc`, `/sys`, `/dev/mem`, `/etc/shadow`

행위 거부: `chmod +s`, `$HOME`·`/` 대상 `rm -rf`, `git push --force`, 인라인 `git -c`,
토큰 출력(`gh auth token` 등), 키체인 도구, 로그인/예약 실행 등록.

### 정직하게: 셸에 대해서는 이것이 경계가 아닙니다

`host.exec` 의 파일 거부 목록은 셸에 대해 **경계가 아니라 과속방지턱**입니다. argv 가 한 번
승인되면 `cat ~/.ssh/id_rsa` 는 돕니다. 셸의 실제 경계는 **리터럴 argv 에 대한 매 호출
사람 검토**와 **인터프리터를 절대 영구 등록하지 않는 것**, 두 가지뿐입니다. 코드 주석에도
같은 말이 적혀 있습니다.

## 감사 로그

`{app_data_dir}/agent-audit/YYYY-MM-DD.jsonl`, append-only, 호출당 **두 레코드**
(실행 전 intent, 실행 후 outcome). 중간에 죽어도 무엇을 시도했는지 남습니다.
`prev = sha256(이전 줄)` 해시 체인이고, head 를 키체인 `audit-head:{user_id}` 에
앵커합니다. 패널에서 다시 검증할 수 있습니다 (`agent_verify_audit`).

**기록합니다**: 시각, 세션, 도구, 정규화된 argv, 해석된 경로, 위험 등급, taint, 결정,
결정 출처, 규칙 id, 소요 시간, 종료 코드, 출력 바이트 수와 sha256.

**기록하지 않습니다**: 파일 내용, stdout 본문, 메시지 본문. 에이전트가 만진 비밀을 전부
두 번째 파일에 복사하는 감사 로그는 통제가 아니라 부채입니다.

append-only 가 특히 중요한 이유: **감사 대상이 파일을 쓸 수 있습니다.** 키체인 앵커에
대해서도 정직하게 — Linux Secret Service 에는 바이너리별 ACL 이 없으므로 앵커는
위조 비용을 올릴 뿐 불가능하게 만들지는 않습니다.

## 아티팩트 (RLM 이음매)

`chat.read_channel` 은 내용이 아니라 핸들을 돌려줍니다.

```json
{ "handle": "art_01J…", "message_count": 214,
  "preview": { "head": ["…"], "tail": ["…"] },
  "inline": "2KB 미만일 때만 전문" }
```

모델은 `artifact.query { handle, op }` 로 더 읽습니다.

- **얻는 것**: 채널 크기와 무관하게 부모 컨텍스트가 유한합니다. 5,000개 메시지 채널이
  ~200토큰 도구 결과 하나가 됩니다. `host.exec` 의 10MB 빌드 로그도 같은 저장소로 갑니다.
- **얻지 못하는 것**: REPL 도 변수도 코드도 없습니다. 고정된 동사로 자르고 거를 뿐
  **계산은 못 합니다**. 재귀도 없습니다.
- **v2 가 추가만 되는 이유**: 루프가 도구 결과를 이미 `{content, artifact}` 로 다룹니다.
  REPL 은 결과가 핸들인 새 핸들러이고, 서브에이전트는 중첩 턴을 돌려 핸들을 반환하는
  핸들러입니다. 루프·스키마·패널을 건드리지 않습니다.

## 저장

`{data_dir}/agent.sqlite3` — **`cache.sqlite3` 와 별개입니다.** 캐시는 스키마를 올릴 때
drop 되고 로그아웃 시 비워집니다. 실제 마이그레이션 래더를 쓰고, 더 새로운 스키마를 만나면
열기를 거부합니다.

테이블: `agent_sessions` · `agent_messages(seq 불변)` · `agent_artifacts` ·
`agent_approvals` · `agent_settings`. `seq` 를 지금 넣어둔 이유는 v2 의 "lineage 를 만드는
압축"이 `replaces_seq_from..to` 를 인용하는 행으로만 가능하기 때문입니다.

**메모리에만 있는 것** (닫으면 사라짐): 승인 grant, taint 플래그, 세션 루트. "패널을 닫으면
끝난다"가 약속이 아니라 구조적 사실이 되도록 세 가지를 같은 곳에 뒀습니다.

**키는 어디에도 저장하지 않습니다** — OS 키체인 계정 `agent-provider:anthropic:{user_id}`
뿐이고, 어느 API 도 되돌려주지 않습니다. `CredentialStore::key` 는 `pub(crate)` 이라
Tauri 명령에서 부를 수 없습니다.

## 레이아웃: 시트는 최대 두 개

Tauri 최소 창폭이 940px 입니다. 스레드 + 미니앱/에이전트 + 전사록 세 열은 **1401px 이상**
에서만 성립합니다 (도크·레일 313 + 문장이 들어가는 전사록 360 + 340 + 380 = 1393).
그 아래는 두 시트가 한 열에 위아래로 쌓이고, **917px 아래**에서는 전사록을 **덮으며**
나눠 갖습니다.

그리고 **에이전트를 열면 미니앱 패널이 닫히고, 그 반대도 마찬가지**입니다. 규칙은
`store/agent.ts` 에 있습니다 — `openAppPanel` 은 호출 지점이 다섯 곳이고, 호출 지점에서
지키는 규칙은 여섯 번째 호출 지점이 생기면 깨지는 규칙입니다.

## 켜지 않은 것: 서버 도구

`web_search` / `web_fetch` 는 Anthropic 인프라에서 돌아 **게이트를 완전히 우회**합니다.
특히 `web_fetch` 는 대화에 이미 있는 URL 을 가져오므로, 공격자가 채널에 심어둔 URL 로
데이터를 실어보낼 수 있습니다. v2 에서도 켜지 않습니다.

### `src-tauri` 는 컴파일 미검증입니다

이 환경에는 webkit2gtk 가 없어서 `src-tauri` 를 빌드할 수 없습니다
(`javascriptcoregtk-4.1` 없음, Amazon Linux 2023 aarch64 에 패키지 없음). `agent_commands.rs`
와 `ToolHost` 실제 구현은 **타입 검사되지 않은 상태로** 들어갑니다. rustfmt 로 파싱만
확인했습니다.

그래서 로직을 최대한 `llack-core` 로 밀었습니다 — vetting, 정책, 감사, 승인, 저장,
abort 추적, 조립까지 전부 core 에 있고 `src-tauri` 는 forwarder 뿐입니다. 이것이 그
분할의 이유입니다.

### 데스크톱 스모크 체크리스트 (사용자 기계에서)

1. 프로바이더 연결 → 앱 재시작 → 여전히 연결됨 (키체인)
2. 잘못된 키로 연결 → 저장되지 않고 "키가 거부되었습니다"
3. 연결 후 설정을 열면 모델 목록이 계정에서 로드됨 → 다른 모델 선택 →
   패널 헤더의 모델 칩이 바뀌고, 재시작 후에도 유지됨
4. 턴 스트리밍 → 중간에 중단 → 부분 답변이 남고 오류가 아님
5. "이 채널 요약해줘" → 도구 카드 → "채널 읽음" 칩이 뜸
6. `host.exec` 승인 → 결과가 아티팩트로 저장됨
7. `host.exec` 거부 → 모델이 다른 방법을 제안하고 턴이 계속됨
8. 채널 게시 승인 → 옆 전사록에 즉시 나타남
9. "이 요약을 ~/notes/summary.md 로 저장해줘" → 승인 카드에 경로·크기·내용
   미리보기 → 승인 → 파일이 생김. 같은 경로에 다시 쓰면 (taint 전) 묻지 않음
10. 채널을 읽은 뒤 같은 쓰기 → 다시 물음 (taint 다운그레이드)
11. 로그아웃 → 다시 로그인 → 프로바이더가 연결되지 않은 상태
