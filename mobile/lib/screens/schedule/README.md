# Schedule Screens

## Overview

The calendar tab: a month grid plus a day list, the event detail bottom sheet,
and the create/edit event dialog. Three top-level helper functions
(`isSameLocalDay`, `isMyScheduleEvent`, `visibleScheduleEvents`,
`calendarDotForDay`) hold the calendar's grouping rules so the grid and the
list can never disagree.

All schedule timestamps arrive from the server in UTC, so every comparison
converts to local time before comparing calendar days.

## Interface

- `bool isSameLocalDay(DateTime a, DateTime b)` — top-level function (`mobile/lib/screens/schedule/schedule_screen.dart`).
- `bool isMyScheduleEvent(ScheduleEvent ev, String? myId)` — top-level function.
- `List<ScheduleEvent> visibleScheduleEvents(List<ScheduleEvent> events, DateTime day, {required bool onlyMyEvents, required String? myId})` — top-level function.
- `({bool show, bool mine}) calendarDotForDay(List<ScheduleEvent> events, DateTime day, {required bool onlyMyEvents, required String? myId})` — top-level function returning a named record.
- `class ScheduleScreen` — public `StatefulWidget` with public field `final bool showCommonActions` and constructor `const ScheduleScreen({super.key, this.showCommonActions = true})`; its State mixes in `AutomaticKeepAliveClientMixin` and returns `wantKeepAlive => true`.
- `Future<void> showEventDetailSheet(BuildContext context, {required ScheduleEvent event, required bool isCreator})` — top-level function (`mobile/lib/screens/schedule/event_detail_sheet.dart`).
- `Future<bool> confirmDeleteEvent(BuildContext context, ScheduleEvent event)` — top-level function.
- `class EventDialog` — public `StatefulWidget` with public fields `final DateTime initialDate` and `final ScheduleEvent? editing` and constructor `const EventDialog({super.key, required this.initialDate, this.editing})` (`mobile/lib/screens/schedule/event_dialog.dart`).

## Invariants

- `[mobile/lib/screens/schedule/schedule_screen.dart:isSameLocalDay]` Both arguments are converted with `.toLocal()` before the year/month/day comparison, because schedules are stored in UTC and comparing a UTC instance against a local date would shift cards by a day.
- `[mobile/lib/screens/schedule/schedule_screen.dart:isMyScheduleEvent]` A null `myId` always yields false; otherwise the event counts as mine if `ev.createdBy == myId` or if `ev.attendees` contains a user whose `user.id == myId`.
- `[mobile/lib/screens/schedule/schedule_screen.dart:visibleScheduleEvents]` Day grouping uses only the start date (`isSameLocalDay(e.startsAt, day)`); all-day events have an exclusive "next day midnight" `ends_at`, so attaching them to the end date would contradict the start-date-based calendar dot. When `onlyMyEvents` is true, events failing `isMyScheduleEvent` are filtered out.
- `[mobile/lib/screens/schedule/schedule_screen.dart:calendarDotForDay]` The dot `show` flag is `dayEvs.isNotEmpty` and `mine` is `dayEvs.any(isMyScheduleEvent)`, and the function delegates to `visibleScheduleEvents` so the day list and the calendar dot always use the same judgment.
- `[mobile/lib/screens/schedule/schedule_screen.dart:_shiftMonth]` Moving a month calls `state.setSelectedDate(DateTime(current.year, current.month + delta, 1))`, so the selection always moves to day 1 of the adjacent month. The displayed month is derived from `state.selectedDate` rather than kept in separate local state.
- `[mobile/lib/screens/schedule/schedule_screen.dart:initState]` A post-frame callback calls `state.loadEvents()` only when `state.hasLoadedEvents` is false, to avoid a duplicate request.
- `[mobile/lib/screens/schedule/schedule_screen.dart:_displayedResponse]` The displayed RSVP is `_pendingRsvp[ev.id] ?? ev.myResponse`, so the optimistic pending value takes priority over the server-confirmed value.
- `[mobile/lib/screens/schedule/schedule_screen.dart:_changeRsvp]` The pending RSVP is written to the map before the request and removed again after the await; on failure the previous server value is restored and `'참석 여부를 바꾸지 못했습니다'` is shown. A `mounted` guard aborts the state update after the await.
- `[mobile/lib/screens/schedule/schedule_screen.dart:_deleteEvent]` The event is not removed locally when the delete fails; instead `'일정을 삭제하지 못했습니다'` is shown and a `mounted` guard stops the update.
- `[mobile/lib/screens/schedule/schedule_screen.dart:build]` The wide two-column layout is chosen when `MediaQuery.sizeOf(context).width >= 650`; the narrow layout keeps the calendar and the day list in a single `ListView`. The day list is padded with 96px of bottom space so the floating action button does not cover the last card.
- `[mobile/lib/screens/schedule/schedule_screen.dart:build]` When `state.eventsError != null` a `SectionErrorBanner` with a `retryEvents` retry action is shown; otherwise, an empty `dayEvents` list renders the `'등록된 일정이 없습니다'` empty state. The `'팀 일정'` legend item is hidden when the `'내 일정만'` filter is active.
- `[mobile/lib/screens/schedule/schedule_screen.dart:_buildMonthGrid]` `firstDayOfWeek` is `DateTime(year, month, 1).weekday % 7` (Sunday = 0) and `daysInMonth` is `DateTime(year, month + 1, 0).day`, and `weekCount` is `((firstDayOfWeek + daysInMonth) / 7).ceil()` so only the needed week rows are drawn. Day numbers outside `1..daysInMonth` render `SizedBox.shrink()`, and the weekday header labels are `['일', '월', '화', '수', '목', '금', '토']` with `'일'` highlighted in `LlackColors.presenceBusy`.
- `[mobile/lib/screens/schedule/schedule_screen.dart:_buildMonthGrid]` The grid uses `SliverGridDelegateWithFixedCrossAxisCount(crossAxisCount: 7, mainAxisExtent: 44)` so the cell height stays fixed when the layout widens. A day cell is highlighted with `LlackColors.accent` when it equals `state.selectedDate` and with `LlackColors.accentSoft` at 0.5 alpha when it equals `DateTime.now()`; the dot color is white when the cell is selected, `LlackColors.accent` for my events and `LlackColors.muted` otherwise.
- `[mobile/lib/screens/schedule/schedule_screen.dart:_buildEventCard]` The time line shows `'하루 종일'` when `ev.allDay`, otherwise `'HH:mm - HH:mm'` formatted from `ev.startsAt.toLocal()` and `ev.endsAt.toLocal()`. The delete `IconButton` is rendered only when `ev.createdBy == myId` and keeps a 44dp minimum touch area. The location row is rendered only when `ev.location.isNotEmpty` and the description block only when `ev.description.isNotEmpty`.
- `[mobile/lib/screens/schedule/schedule_screen.dart:_buildRsvpChip]` RSVP chips expose exactly three choices — `'참석'` for `EventResponse.accepted`, `'미정'` for `EventResponse.tentative`, `'불참'` for `EventResponse.declined` — and enforce a 44dp minimum height.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:showEventDetailSheet]` The sheet is opened with `showModalBottomSheet<void>` using `isScrollControlled: true` and a transparent background so the keyboard does not hide the content.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:confirmDeleteEvent]` The confirmation returns true only when the dialog result equals `true`, so both the `'취소'` pop with false and a null result are treated as a decline.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:_EventDetailSheet]` The displayed event is looked up in `state.events` by `eventId` with `orElse: () => initialEvent`, so values edited elsewhere are re-read from state. The sheet is constrained to `MediaQuery.sizeOf(context).height * 0.85` and its bottom padding is animated over 180ms with `Curves.easeOut` to follow the keyboard inset. The `'나'` badge is shown only for the attendee whose `a.user.id == myId`.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:_creatorName]` The creator name is resolved from `state.members` by `m.user.id == event.createdBy`, falling back to `'알 수 없음'` when the creator is not a member.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:_channelName]` The `'연결 채널'` row is omitted when `event.channelId` is null or when the channel is not found in `state.allChannels`; a found channel is rendered as `'# ${c.name}'`. The edit and delete buttons are shown only when `isCreator` is true.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:_delete]` The deletion first awaits `confirmDeleteEvent` and returns without touching the state when it returns false; on failure the sheet is not popped and `'일정을 삭제하지 못했습니다'` is shown, and on success `Navigator.pop(context)` closes the sheet.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:_dateTimeText]` An all-day event renders as `'$day · 하루 종일'`; a same-day event renders `'$day · $time'`; a cross-day event renders `'$day $time ~ ${DateFormat('M월 d일 HH:mm').format(end)}'`.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:_ResponseBadge]` The badge color mapping is exhaustive over `EventResponse`: accepted → `LlackColors.accent`, tentative → `LlackColors.presenceAway`, declined → `LlackColors.presenceBusy`, pending → `LlackColors.muted`.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:_EventDetailSheet]` The attendee list shows `'참석자가 없습니다.'` when `event.attendees.isEmpty`, otherwise one row per attendee, and the RSVP badge sits outside the `Expanded` so it always stays at the row's right edge.
- `[mobile/lib/screens/schedule/event_dialog.dart:_submit]` Submission is aborted when the trimmed title is empty, making the title the only required field.
- `[mobile/lib/screens/schedule/event_dialog.dart:initState]` In edit mode every field is initialized from the existing event (title, description, location, `startsAt.toLocal()`, `endsAt.toLocal()`, `allDay`, `isPrivate`, `channelId`, and attendee ids); in create mode the start date and end date both default to `widget.initialDate` with a 10:00 start and an 11:00 end.
- `[mobile/lib/screens/schedule/event_dialog.dart:_submit]` When `_allDay` is true the start is forced to 00:00 and the end to 23:59 of the chosen dates. In edit mode the trimmed description and location are always sent (as empty strings when cleared) so the user can actually erase them; in create mode empty description/location are sent as null, and `attendeeIds` is sent as null when no attendee is selected.
- `[mobile/lib/screens/schedule/event_dialog.dart:_submit]` On a failed update the dialog is not closed, `_isSubmitting` is reset to false and `'일정 수정 실패: 서버에 저장하지 못했습니다'` is shown; on success the dialog pops. A thrown exception is caught and reported as `'일정 수정 실패: $e'` or `'일정 등록 실패: $e'` depending on edit mode.
- `[mobile/lib/screens/schedule/event_dialog.dart:build]` The start date picker allows `DateTime(2020)`..`DateTime(2035)` and the end date picker allows `_startDate`..`DateTime(2035)`, so the end date can never precede the start date. When a new start date is picked and `_endDate.isBefore(d)` holds, `_endDate` is moved to the same date `d`. The time pickers for start and end are hidden while `_allDay` is true. The submit `ElevatedButton` is disabled while `_isSubmitting` is true and renders a `CircularProgressIndicator` instead of its label.
- `[mobile/lib/screens/schedule/event_dialog.dart:_ChannelDropdownField]` The dropdown value is sanitized to `value != null && channels.any((c) => c.id == value) ? value : null` and the widget key is `ValueKey<String?>('channel-$valid')`, which the comment states avoids the DropdownButton "exactly one item" assertion when the selected channel disappears from the list. The dialog is constrained to `BoxConstraints(maxWidth: 500, maxHeight: 650)` and the channel dropdown always offers a null-value `'연결 안 함'` item.

## Side Effects

- `[mobile/lib/screens/schedule/schedule_screen.dart:initState]` Registers a `WidgetsBinding.instance.addPostFrameCallback` that calls `context.read<AppState>()` and, when `hasLoadedEvents` is false, triggers `state.loadEvents()`.
- `[mobile/lib/screens/schedule/schedule_screen.dart:build]` Reads app state through `context.watch<AppState>()`, consuming `currentUser?.id`, `selectedDate`, `events`, `onlyMyEvents`, `eventsError` and `hasLoadedEvents`.
- `[mobile/lib/screens/schedule/schedule_screen.dart:_shiftMonth]` Writes to the provider via `state.setSelectedDate(...)`; tapping a day cell does the same. The `'내 일정만'` `FilterChip` calls `state.toggleOnlyMyEvents()`.
- `[mobile/lib/screens/schedule/schedule_screen.dart:build]` The `RefreshIndicator` `onRefresh` calls `state.loadEvents()`; the error banner's `onRetry` calls `context.read<AppState>().retryEvents()`. The floating action button opens `showDialog` with `EventDialog(initialDate: selectedDate)`.
- `[mobile/lib/screens/schedule/schedule_screen.dart:_buildEventCard]` Tapping the card calls `showEventDetailSheet(context, event: ev, isCreator: isCreator)`; the delete button first awaits `confirmDeleteEvent(context, ev)` and only then calls `_deleteEvent(ev)`.
- `[mobile/lib/screens/schedule/schedule_screen.dart:_changeRsvp]` Calls `state.rsvpEvent(ev.id, response)` (`POST /events/$eventId/rsvp`) and calls `setState` to mutate the `_pendingRsvp` map before and after the request; on failure it shows `showAppSnackBar(context, '참석 여부를 바꾸지 못했습니다')`.
- `[mobile/lib/screens/schedule/schedule_screen.dart:_deleteEvent]` Calls `state.deleteEvent(ev.id)` (`DELETE /events/$eventId`) and shows `showAppSnackBar(context, '일정을 삭제하지 못했습니다')` on failure.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:showEventDetailSheet]` Opens a `showModalBottomSheet<void>` whose builder returns `_EventDetailSheet(eventId: event.id, initialEvent: event, isCreator: isCreator)`.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:confirmDeleteEvent]` Opens `showDialog<bool>` with an `AlertDialog` whose `'취소'` button pops with false and whose `'삭제'` button pops with true.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:_edit]` Opens `showDialog<void>` with `EventDialog(initialDate: event.startsAt.toLocal(), editing: event)`.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:_delete]` Calls `state.deleteEvent(event.id)` via `context.read<AppState>()`, shows `showAppSnackBar(context, '일정을 삭제하지 못했습니다')` on failure, and calls `Navigator.pop(context)` to close the sheet on success.
- `[mobile/lib/screens/schedule/event_detail_sheet.dart:_EventDetailSheet]` Reads app state through `context.watch<AppState>()`, consuming `state.events`, `state.currentUser?.id`, `state.members` and `state.allChannels`.
- `[mobile/lib/screens/schedule/event_dialog.dart:_submit]` Calls `state.updateEvent(eventId: editing.id, title: ..., description: ..., location: ..., startsAt: ..., endsAt: ..., allDay: ..., isPrivate: ..., channelId: ..., attendeeIds: ...)` in edit mode (`PATCH /events/$eventId`) and `state.createEvent(title: ..., ...)` in create mode (`POST /workspaces/$workspaceId/events`), then calls `Navigator.pop(context)` on success and `showAppSnackBar(context, ...)` on failure or on a caught exception.
- `[mobile/lib/screens/schedule/event_dialog.dart:build]` Opens `showDatePicker` for the start date (`initialDate: _startDate`, `firstDate: DateTime(2020)`, `lastDate: DateTime(2035)`) and for the end date (`initialDate: _endDate`, `firstDate: _startDate`, `lastDate: DateTime(2035)`), and `showTimePicker` for the start and end times. The `'하루 종일'` and `'비공개 일정'` SwitchListTiles toggle `_allDay` and `_isPrivate`, and the attendee FilterChips add/remove ids in `_selectedAttendeeIds`. The three `TextEditingController`s (`_titleCtrl`, `_descCtrl`, `_locationCtrl`) are created in `initState` and disposed in `dispose()`.
