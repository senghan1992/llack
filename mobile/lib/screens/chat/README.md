# Chat Screens

## Overview

The chat area: the channel/DM list (`ChatTab`), the conversation pane
(`ChatScreen`), the thread view (`ThreadScreen`), and the supporting dialogs
and sheets.

`ChatScreen` is the most stateful widget in the app. It owns infinite scroll in
both directions, per-channel scroll restoration (`ChatScrollMemory`), per-channel
draft restoration, attachment upload/send wiring, a "jump to latest" control,
and the "jump to a specific message" flow used by search results and
notifications. `ChannelSettingsSheet` edits channel metadata and deletes a
channel after confirmation; `PeoplePickerSheet` adds workspace members to a
channel.

`ChatNavigator` is the single navigation seam for the chat area: both the
channel list and the search dialog go through it so a route is pushed only on
compact form factors.

## Interface

- `class ChatScreen` — public `StatefulWidget` with a single public field `final bool showBackButton` and constructor `const ChatScreen({super.key, this.showBackButton = false})` (`mobile/lib/screens/chat/chat_screen.dart`).
- `class ChatTab` — public `StatelessWidget` with constructor `const ChatTab({super.key})`; no public fields (`mobile/lib/screens/chat/chat_tab.dart`).
- `class ChannelInfoDialog` — public `StatefulWidget` with public field `final Channel channel` and constructor `const ChannelInfoDialog({super.key, required this.channel})` (`mobile/lib/screens/chat/channel_info_dialog.dart`).
- `class ChannelSettingsSheet` — public `StatefulWidget` with public field `final Channel channel` and constructor `const ChannelSettingsSheet({super.key, required this.channel})` (`mobile/lib/screens/chat/channel_settings_sheet.dart`).
- `class PeoplePickerSheet` — public `StatefulWidget` with public field `final Channel channel` and constructor `const PeoplePickerSheet({super.key, required this.channel})` (`mobile/lib/screens/chat/people_picker_sheet.dart`).
- `class ChatMessageItem` — public `StatelessWidget` with final fields `Message message`, `bool isMine`, `bool showDateHeader`, `int deletedCount` (default 1), `Key? jumpKey`, `bool highlight` (default false), `String Function(String url)? fileUrlResolver`, `VoidCallback? onOpenThread`, `VoidCallback? onReplyInline`, `void Function(String emoji)? onToggleReaction`, `VoidCallback? onTogglePin`, `void Function(String newBody)? onEdit`, `VoidCallback? onDelete`, `void Function(Reaction reaction)? onShowReactionParticipants` (`mobile/lib/screens/chat/chat_message_item.dart`).
- `class ChatMessagesErrorState` — public `StatelessWidget` with final fields `String message` and `VoidCallback onRetry` (`mobile/lib/screens/chat/chat_messages_error_state.dart`).
- `class ChatNavigator` — public final class with a private constructor, exposing only static members:
  - `static void ChatNavigator.openChannel({required AppState state, required NavigatorState navigator, required String channelId, bool push = true, String? messageId})`
  - `static Future<void> ChatNavigator.openDm({required AppState state, required NavigatorState navigator, required String userId, bool push = true})`
  - `static String ChatNavigator.describeDmError(Object error)`
  (`mobile/lib/screens/chat/chat_navigator.dart`)
- `class ChatScrollMemory` — public final class with a private constructor and static methods `static void save(String channelId, double distance)` / `static double load(String channelId)` (`mobile/lib/screens/chat/chat_scroll_memory.dart`).
- `class MessageActions` — public final class with a private constructor, exposing only static members:
  - `@visibleForTesting static SnackBar MessageActions.buildDeleteSnackBar({required VoidCallback onUndo})`
  - `static Future<void> MessageActions.deleteMessage(BuildContext context, Message message, String channelId)`
  - `static Future<void> MessageActions.showReactionParticipants(BuildContext context, Reaction reaction)`
  (`mobile/lib/screens/chat/message_actions.dart`)
- `class MessageDateHeader` — public `StatelessWidget` with final field `DateTime date` (`mobile/lib/screens/chat/message_date_header.dart`).
- `class NewChannelDialog` — public `StatefulWidget` with const constructor `NewChannelDialog({super.key})` (`mobile/lib/screens/chat/new_channel_dialog.dart`).
- `class NewDmDialog` — public `StatefulWidget` with const constructor `NewDmDialog({super.key})` (`mobile/lib/screens/chat/new_dm_dialog.dart`).
- `class ThreadScreen` — public `StatefulWidget` with final field `Message rootMessage` and constructor `const ThreadScreen({super.key, required this.rootMessage})` (`mobile/lib/screens/chat/thread_screen.dart`).

## Invariants

- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState.initState]` The visibility hook `(cid) => _isNearBottom()` is registered on `_state.isNewestMessageVisible` only while the chat screen is open.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._handleDraftChanged]` Draft text is stored both in the screen-local `_drafts` map and in `AppState.setDraft`, keyed by channel id. On a successful send both copies are cleared.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._restoreDraftIntoComposer]` When the active channel changes, the pending draft is captured before the new composer reports its initial empty text. The composer is recreated with a channel/generation key, and the captured text is restored after the frame without emitting a typing signal.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._updateJumpButton]` The "최신 메시지" button is shown only when the list is not near the bottom and the screen is not already auto-scrolling; pressing it calls `_scrollToBottom(animate: true)`.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._uploadAttachments]` Picked files are uploaded one at a time with `state.uploadFile(path, fileName: file.name)`. The returned ids are paired with the file names for the composer, and any upload exception stops the operation and shows a failure snackbar.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState.dispose]` `isNewestMessageVisible` is reset to null only when `identical(_state.isNewestMessageVisible, _visibilityHook)`, so another chat screen's hook is not clobbered.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._onScroll]` Older messages are requested when `position.pixels <= position.minScrollExtent + 80`, and newer messages when `position.pixels >= position.maxScrollExtent - 80`.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._isNearBottom]` The "near bottom" test is `p.maxScrollExtent - p.pixels <= 120`; it returns `true` when the scroll controller has no clients.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._markReadIfUnread]` Read marking is gated: it returns early unless the active channel exists and `channel.unreadCount > 0`, so an already-read channel sends no read signal.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._loadNewer]` `_loadNewer` returns early when `_loadingNewer || _isJumping`, when `activeChannelId` is null, or when `hasMoreNewerMessages` is false.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._loadOlder]` `_loadOlder` returns early when `_loadingOlder || _isJumping`, when there is no active channel, or when `hasMoreActiveMessages` is false / `isLoadingActiveMessages` is true. After older messages are prepended, the scroll offset is corrected by the growth of `maxScrollExtent` (`delta = p.maxScrollExtent - beforeMax`) and clamped to `[minScrollExtent, maxScrollExtent]` so the viewed message does not shift.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._performJump]` The jump is retried at most `_maxJumpRetries` (10) times across post-frame callbacks; when the retry budget is exceeded `_failJump` is called.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._failJump]` `_failedJumpTarget` is recorded synchronously to prevent retrying the same missing target, and `state.clearPendingFocusMessageId()` is called so `build` cannot re-enter an infinite jump loop.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._handleUserScroll]` Scroll notifications during a jump are ignored (`if (_isJumping) return false;`), and the highlight is cleared only when `notification.direction != ScrollDirection.idle`; the handler always returns false.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._syncScroll]` Position restoration is skipped while `_isJumping` is true, and a pending restore distance is only applied when `context.read<AppState>().activeMessages` is non-empty.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._scrollToBottom]` After the animation, if `pos.maxScrollExtent - pos.pixels > 8` the controller jumps to `pos.maxScrollExtent` again to compensate for late layout.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState.build]` When `channelId != _channelId` the channel changed: `_failedJumpTarget` and `_highlightedMessageId` are cleared, `_pendingRestoreDistance` is reloaded from `ChatScrollMemory.load(channelId)`, and `_lastMessageCount` is reset to 0.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState.build]` Auto-follow to the newest message is enabled only when the message list grew and `!_loadingOlder && !_isJumping && _pendingRestoreDistance == null && _isNearBottom()`. A pending focus jump starts only when `focusId != null && !_isJumping && focusId != _failedJumpTarget`; if the message is absent and loading has finished, `_failJump(focusId)` is called instead.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState.build]` A rising keyboard inset (`keyboardInset > _lastKeyboardInset`) while `_isNearBottom()` sets `_followBottom = true` so the newest message stays visible. The `jumpKey` GlobalKey is attached only to the item whose `msg.id == focusId`, so a jump targets exactly one message.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState.build]` Consecutive deleted messages are collapsed into a single rendered item with `deletedCount: run` (items after the first deleted one return `SizedBox.shrink()`). A date header is shown for index 0 or when the previous message's `createdAt` is not the same calendar day, compared by `_isSameDay`.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState.build]` Empty states are gated: a null channel renders `'선택된 대화방이 없습니다...'`, an empty list with no error renders `'아직 메시지가 없습니다...'`, and an empty list with `state.messagesError != null` renders `ChatMessagesErrorState` with `state.retryMessages` as the retry callback.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState.build]` The top loading bar (`LinearProgressIndicator`) is shown only when `state.isLoadingActiveMessages && messages.isNotEmpty`, and the `ListView` is replaced by a spinner while loading with an empty list. The list uses `scrollCacheExtent` of `_jumpCacheExtent` (100000) while jumping and `_defaultCacheExtent` (250) otherwise. The app bar's leading button is only implied when `widget.showBackButton` is true. The typing indicator is rendered only when `typingUsers.isNotEmpty`, and the topic strip only when `channel.topic != null && channel.topic!.isNotEmpty`.
- `[mobile/lib/screens/chat/chat_tab.dart:ChatTab._onSelectChannel]` The chat is opened with `push: formFactor.isCompact`, so on tablet-sized form factors no route is pushed because the conversation pane is already visible beside the list.
- `[mobile/lib/screens/chat/chat_tab.dart:ChatTab._openBrowseChannels]` The "채널 찾아보기" row opens a sheet of non-DM channels for which `isMember` is false. A successful `state.joinChannel(channel.id)` closes the sheet with the joined channel id, and the chat then opens that channel through `ChatNavigator`.
- `[mobile/lib/screens/chat/chat_tab.dart:_BrowseChannelsSheetState._join]` Join failures are caught in the sheet, leave the channel in the candidate list, and show `'채널에 참가하지 못했습니다. 잠시 후 다시 시도해주세요.'`; a successful join shows a confirmation snackbar before returning the channel id.
- `[mobile/lib/screens/chat/chat_tab.dart:ChatTab.build]` The pull-to-refresh handler calls `state.refreshWorkspace()` and not `boot()`, because `boot()` is cold-start only and would replace the whole app with the splash screen (and log out when offline). The channel error banner is shown only when `state.channelsError != null`, and `'채널이 없습니다'` is shown only when `channels.isEmpty && state.channelsError == null`. `'진행 중인 1:1 대화가 없습니다'` is shown when `dms.isEmpty`.
- `[mobile/lib/screens/chat/chat_tab.dart:ChatTab._buildDmTile]` The DM counterpart is resolved as `dm.dmUser` first, otherwise the first member whose id differs from the current user's id, falling back to `dm.members!.first`, and finally to a placeholder `User(id: '', email: '', name: dm.name)`.
- `[mobile/lib/screens/chat/chat_tab.dart:ChatTab._buildSectionHeader]` The add button enforces a minimum 44dp touch target via `constraints: const BoxConstraints(minWidth: 44, minHeight: 44)` because the icon itself is only 22dp.
- `[mobile/lib/screens/chat/chat_tab.dart:ChatTab._buildChannelTile]` Channel tiles place the `ListTile` inside a `Material` with the selection background color, so the ListTile ink splash is not hidden by a colored Container underneath. An unread badge is rendered only when `channel.unreadCount > 0`, and the title is bold when the channel is selected or has unread messages.
- `[mobile/lib/screens/chat/channel_info_dialog.dart:_ChannelInfoDialogState.initState]` Both `_loadPins()` and `_loadMembers()` are kicked off when the dialog is created.
- `[mobile/lib/screens/chat/channel_info_dialog.dart:_ChannelInfoDialogState._latestChannel]` The dialog resolves the current channel from `state.allChannels` by id instead of continuing to render the original snapshot after a settings change.
- `[mobile/lib/screens/chat/channel_info_dialog.dart:_ChannelInfoDialogState._openSettings]` For non-DM channels, the settings button opens `ChannelSettingsSheet` above the still-open info dialog. Returning from the sheet triggers a rebuild so the updated name and topic are visible.
- `[mobile/lib/screens/chat/channel_info_dialog.dart:_ChannelInfoDialogState._openPeoplePicker]` For non-DM channels, the "사람 추가" button opens `PeoplePickerSheet`; after it closes, the info dialog reloads channel members.
- `[mobile/lib/screens/chat/channel_info_dialog.dart:_ChannelInfoDialogState._loadMembers]` Members are fetched through `state.membersForChannel(widget.channel.id)` because bootstrap does not contain channel members; on failure `_loadingMembers` is set to false and the member list stays empty.
- `[mobile/lib/screens/chat/channel_info_dialog.dart:_ChannelInfoDialogState._loadPins]` Pins are fetched through `state.api.getPins(widget.channel.id)`; on failure `_loadingPins` is set to false and the pin list stays empty.
- `[mobile/lib/screens/chat/channel_info_dialog.dart:_ChannelInfoDialogState._leaveOrDelete]` The destructive action runs only after `showDialog<bool>` returns `true` and `context.mounted` is true; the confirm dialog's cancel button pops with `false` and the action button pops with `true`. The delete/leave request is performed *before* the info dialog is closed (the dialog is popped only at the end), so the failure snackbar is shown while the dialog is still open; the failure text is `'대화를 삭제하지 못했습니다'` for DMs and `'채널을 나가지 못했습니다'` otherwise.
- `[mobile/lib/screens/chat/channel_info_dialog.dart:_ChannelInfoDialogState.build]` The member count label shows `_members.length` when members were loaded and falls back to `channel.memberCount` otherwise. The empty state is shown when `_members.isEmpty` and `'고정된 메시지가 없습니다'` when `_pins.isEmpty`; the dialog is constrained to `maxWidth: 480, maxHeight: 600` and the pin list to `maxHeight: 120`.
- `[mobile/lib/screens/chat/channel_settings_sheet.dart:_ChannelSettingsSheetState._save]` A blank trimmed channel name blocks saving. `state.updateChannel` returns `true` only after a successful request; on `false` the sheet stays open, preserves the entered values, and shows a failure snackbar.
- `[mobile/lib/screens/chat/channel_settings_sheet.dart:_ChannelSettingsSheetState._deleteChannel]` Channel deletion requires the confirmation dialog to return exactly `true`. `state.deleteChannel` is then called; a `false` result keeps the sheet open and no local deletion is assumed.
- `[mobile/lib/screens/chat/people_picker_sheet.dart:_PeoplePickerSheetState._candidates]` Candidates are workspace members who are neither current channel members nor users just added. The local filter matches the trimmed, lower-cased name, email, or title.
- `[mobile/lib/screens/chat/people_picker_sheet.dart:_PeoplePickerSheetState._add]` A successful `state.addChannelMember` removes that user from the candidates immediately; a `false` result leaves the user available for another attempt and shows a failure snackbar.
- `[mobile/lib/screens/chat/chat_message_item.dart:ChatMessageItem.deletedCount]` `deletedCount` defaults to 1 and the code comment states deleted messages are drawn as a quiet single line, with consecutive deletions merged into one.
- `[mobile/lib/screens/chat/chat_message_item.dart:ChatMessageItem.showDateHeader]` The date header is drawn only when `showDateHeader` is true, and `jumpKey` is non-null only for the jump-target message.
- `[mobile/lib/screens/chat/chat_messages_error_state.dart:ChatMessagesErrorState]` The widget is deliberately distinguished from the empty state by rendering a `'다시 시도'` retry button.
- `[mobile/lib/screens/chat/chat_navigator.dart:ChatNavigator.openChannel]` When `messageId` is non-null it calls `state.selectChannel(channelId, focusMessageId: messageId)`, otherwise `state.selectChannel(channelId)`; when `push` is false the method returns before navigating, so no route is pushed on tablet layouts.
- `[mobile/lib/screens/chat/chat_navigator.dart:ChatNavigator.openDm]` The method awaits `state.openDm(userId)` before pushing, and returns without pushing when `push` is false.
- `[mobile/lib/screens/chat/chat_navigator.dart:ChatNavigator.describeDmError]` For an `ApiException` the status codes map literally as written: 422 → `'자신과의 1:1 대화는 만들 수 없습니다.'`, 403 → `'이 사람은 이 워크스페이스의 멤버가 아닙니다.'`, 404 → `'사용자를 찾을 수 없습니다.'`, 409 → `'이미 대화가 있습니다.'`; codes `'timeout'` and `'network'` produce dedicated messages; any other status produces `'대화를 열지 못했습니다 (오류 ${error.status}). 잠시 후 다시 시도해주세요.'`; a non-`ApiException` error returns `'대화를 열지 못했습니다. 잠시 후 다시 시도해주세요.'`.
- `[mobile/lib/screens/chat/chat_scroll_memory.dart:ChatScrollMemory]` The stored value is the distance from the newest message rather than a pixel offset, so that newly arriving messages do not push the user's visible message off screen. `load` returns 0 when no distance was saved for the channel.
- `[mobile/lib/screens/chat/message_actions.dart:MessageActions.buildDeleteSnackBar]` The SnackBar explicitly sets `persist: false` because Flutter's constructor computes `persist = persist ?? action != null`, which would otherwise disable auto-dismiss; the duration is fixed at 10 seconds.
- `[mobile/lib/screens/chat/message_actions.dart:MessageActions.deleteMessage]` A failed deletion shows `'메시지를 삭제하지 못했습니다'` and returns without showing the undo SnackBar; on success `messenger.hideCurrentSnackBar()` runs before showing the undo SnackBar. On successful undo no extra notice is shown; on failure `'메시지를 복구하지 못했습니다'` is shown.
- `[mobile/lib/screens/chat/message_actions.dart:MessageActions._show]` The helper returns early if `!messenger.mounted`. The doc comment requires the passed `context` to come from inside the `ScaffoldMessenger` that should draw the SnackBar, so a nested messenger in `ChatScreen` keeps the SnackBar out of the composer area.
- `[mobile/lib/screens/chat/message_actions.dart:MessageActions._participantNames]` Reaction participant names are resolved from `AppState.members`. An id that is not in the member list is shortened to its first eight characters, and an empty result shows the reaction count instead of a name list.
- `[mobile/lib/widgets/message_bubble.dart:MessageBubble._showReactionParticipants]` A long press on a reaction chip calls the optional `onShowReactionParticipants` callback, or falls back directly to `MessageActions.showReactionParticipants` when no override is supplied.
- `[mobile/lib/screens/chat/message_date_header.dart:MessageDateHeader._format]` The date is formatted with the `'yyyy년 M월 d일 EEEE'` pattern under the `'ko_KR'` locale using `date.toLocal()`.
- `[mobile/lib/screens/chat/new_channel_dialog.dart:_NewChannelDialogState._submit]` Submission is gated on a non-empty trimmed channel name (`if (name.isEmpty) return;`). The topic is passed as `null` when the trimmed text is empty and `memberIds` as `null` when no members are selected. While `_isCreating` is true the create button's `onPressed` is null and a `CircularProgressIndicator` is shown instead of the `'만들기'` label; on failure `_isCreating` is reset to false. After a successful create the dialog pops only when `mounted` is true, and errors are reported with `showAppSnackBar(context, '생성 실패: $e')`.
- `[mobile/lib/screens/chat/new_channel_dialog.dart:_NewChannelDialogState.build]` The member checklist lists only members whose `m.user.id != myId`, excluding the current user.
- `[mobile/lib/screens/chat/new_dm_dialog.dart:_NewDmDialogState._startDm]` The DM route is pushed only when `FormFactor(context).isCompact` is true, because on tablet the chat pane is already visible.
- `[mobile/lib/screens/chat/new_dm_dialog.dart:_NewDmDialogState.build]` The current user is excluded from the member list, and the filter is matched case-insensitively against name, email, and title. The empty-state text differs by condition: `'멤버가 없습니다'` when no filter is applied and `'검색 결과가 없습니다'` when a filter yields nothing.
- `[mobile/lib/screens/chat/thread_screen.dart:_ThreadScreenState.build]` The reply list comes from `state.threadReplies` and the loading flag from `state.isLoadingReplies`; a `CircularProgressIndicator` is shown while loading, the empty-reply text `'아직 답글이 없습니다. 첫 답글을 남겨보세요.'` is shown when replies are empty. The composer's `onSend` returns `false` when `state.sendReply(text)` returns false, which makes the composer restore the text and show a failure notice; on success the list animates to `maxScrollExtent` after a 100 ms delay, guarded by `_scrollController.hasClients`. The root message bubble exposes delete, reaction and pin callbacks but no `onEdit`, while reply bubbles additionally expose `onEdit` (mapped to `state.editMessage(reply.id, newBody)`).

## Side Effects

- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState.initState]` Registers the visibility hook by writing `_state.isNewestMessageVisible = _visibilityHook` on the `AppState` provider, and attaches `_onScroll` to `_scrollController`.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState.dispose]` Clears `_state.isNewestMessageVisible` when the hook is still its own, and disposes `_scrollController`.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._onScroll]` Persists per-channel scroll distance through `ChatScrollMemory.save(cid, position.maxScrollExtent - position.pixels)`.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._markReadIfUnread]` Calls `_state.markChannelRead(cid)`, which sends the read signal over the realtime channel.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._loadNewer]` Calls `state.loadNewerMessages(cid)` — `GET /channels/$channelId/messages?limit=40&after=$cursor`.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._loadOlder]` Calls `state.loadMessages(cid, more: true)` — `GET /channels/$channelId/messages?limit=40&before=$beforeId`.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._openThread]` Calls `state.openThread(msg)` (`GET /messages/$messageId/replies?limit=100`) and pushes `MaterialPageRoute(builder: (_) => ThreadScreen(rootMessage: msg))` via `Navigator.push`.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._failJump]` Shows a SnackBar with the text `'해당 메시지를 찾을 수 없습니다. 이미 삭제되었을 수 있어요.'` on the screen-local `ScaffoldMessenger` (`_messengerKey`) after calling `hideCurrentSnackBar()`, and calls `state.clearPendingFocusMessageId()`.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState.build]` When `state.focusErrorMessage != null` it shows that text as a SnackBar on `_messengerKey` and calls `context.read<AppState>().clearFocusErrorMessage()`. The app bar title InkWell and the `'채널 정보'` IconButton both call `showDialog(context: context, builder: (_) => ChannelInfoDialog(channel: channel))`. Message item callbacks call `state.toggleReaction(msg, emoji)`, `state.togglePin(msg)`, `state.editMessage(msg.id, newBody)`, `state.setReplyTo(msg)` and `state.clearReplyTo`. Deletion is delegated to `MessageActions.deleteMessage(ctx, msg, channel.id)`. The composer is wired to `state.sendTyping(typing, channel.id)`, `state.sendMessage(text)`, and `state.sendMessage(text, attachmentIds: attachmentIds)`; on success the channel draft is cleared, the highlight is cleared, and `_scrollToBottom(animate: true)` runs. Attachment URLs are resolved with `state.api.absoluteFileUrl`.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._uploadAttachments]` Opens the platform file picker and uploads each selected local file through `state.uploadFile` before the message is sent.
- `[mobile/lib/screens/chat/chat_screen.dart:_ChatScreenState._handleDraftChanged]` Writes each composer change to the screen-local draft map and `state.setDraft(channelId, text)`; successful sends remove that channel's draft.
- `[mobile/lib/screens/chat/chat_tab.dart:ChatTab.build]` The `RefreshIndicator` triggers `state.refreshWorkspace()` (`GET /workspaces/$workspaceId/bootstrap`); the error banner's `'다시 시도'` button calls `state.retryChannels()`. Section header buttons call `showDialog` with `NewChannelDialog` and `NewDmDialog`. DM presence is read with `state.getPresence(otherUser.id)`.
- `[mobile/lib/screens/chat/chat_tab.dart:ChatTab._onSelectChannel]` Calls `ChatNavigator.openChannel(state: state, navigator: Navigator.of(context, rootNavigator: true), channelId: channel.id, push: formFactor.isCompact)`.
- `[mobile/lib/screens/chat/chat_tab.dart:_BrowseChannelsSheetState._join]` Calls `state.joinChannel(channel.id)` (`POST /channels/$channelId/join`) and, on success, opens the joined channel through `ChatNavigator.openChannel`.
- `[mobile/lib/screens/chat/channel_info_dialog.dart:_ChannelInfoDialogState._loadPins]` Calls `state.api.getPins(widget.channel.id)` — `GET /channels/$channelId/pins`.
