# Projects Screens

## Overview

The project tab: a scoped project picker, a seven-tab task board, the task
detail bottom sheet, and the create/edit task dialog. The board combines the
four task-status columns with milestone, "my tasks", and timeline views.

`ProjectSettingsSheet` is the shared create/edit surface for projects. It owns
project metadata, linked channel, membership, archive state, and confirmed
deletion. `MilestonePanel` and `MilestoneDialog` manage dated milestones and
their task links, while `TimelinePanel` lays the milestone periods out on a
shared date range.

## Interface

- `class ProjectsScreen` — public `StatefulWidget` with the public field `final bool showCommonActions` and constructor `const ProjectsScreen({super.key, this.showCommonActions = true})`; its State mixes in `SingleTickerProviderStateMixin` and `AutomaticKeepAliveClientMixin` (`mobile/lib/screens/projects/projects_screen.dart`).
- `class ProjectSettingsSheet` — public `StatefulWidget` with public field `final Project? project` and constructor `const ProjectSettingsSheet({super.key, this.project})`; a null project means create mode (`mobile/lib/screens/projects/project_settings_sheet.dart`).
- `const List<String> kMilestonePresetColors` — the six selectable milestone colors (`mobile/lib/screens/projects/milestone_sheet.dart`).
- `Color milestoneColor(String? hex)` — converts a server hex color to a Flutter `Color`, falling back to `LlackColors.accent` for an empty or invalid value (`mobile/lib/screens/projects/milestone_sheet.dart`).
- `Future<void> showMilestoneDialog(BuildContext context, {Milestone? milestone})` — opens `MilestoneDialog` in create or edit mode (`mobile/lib/screens/projects/milestone_sheet.dart`).
- `class MilestonePanel` — public `StatelessWidget` with const constructor `const MilestonePanel({super.key})`; lists the active project's milestones and opens the create/edit dialog (`mobile/lib/screens/projects/milestone_sheet.dart`).
- `class TimelinePanel` — public `StatelessWidget` with const constructor `const TimelinePanel({super.key})`; draws milestone periods over their shared date range (`mobile/lib/screens/projects/milestone_sheet.dart`).
- `class MilestoneDialog` — public `StatefulWidget` with public field `final Milestone? milestone` and constructor `const MilestoneDialog({super.key, this.milestone})`; a null milestone means create mode (`mobile/lib/screens/projects/milestone_sheet.dart`).
- `class MyTasksScreen` — public `StatelessWidget` with const constructor `const MyTasksScreen({super.key})` (`mobile/lib/screens/projects/my_tasks_screen.dart`).
- `class TaskDetailSheet` — public `StatefulWidget` with the required public field `final Task task` and constructor `const TaskDetailSheet({super.key, required this.task})` (`mobile/lib/screens/projects/task_detail_sheet.dart`).
- `class TaskDialog` — public `StatefulWidget` with public fields `final TaskStatus initialStatus` and `final Task? editing` (null means create mode) and constructor `const TaskDialog({super.key, this.initialStatus = TaskStatus.todo, this.editing})` (`mobile/lib/screens/projects/task_dialog.dart`).

## Invariants

- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState.initState]` The board `TabController` has length 7 and starts at the file-level `_boardTabIndex`; the separate `_taskStatusFilterIndex` remembers the last selected status column. Both notifiers live at file scope so rotation does not reset the selected view.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState._syncTabIndex]` The board tab order is request, todo, in progress, done, milestone, my tasks, and timeline. Only indices 0-3 update `_taskStatusFilterIndex`; entering the "my tasks" tab reloads `state.myTasks`.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState._onShellTabChanged]` Returning to the project shell tab reloads the workspace-wide "my tasks" list.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState.initState]` `state.loadProjects()` is called in a post-frame callback only when `!state.hasLoadedProjects`; the code comment states emptiness of the list is not used as the success signal (duplicate-request prevention).
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState._visibleProjects]` The "전체" scope includes every project, while the "내 프로젝트" scope includes only projects whose `isMember` flag is true. The dropdown, task board, and empty state all use the visible subset.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState._setScope]` If the selected project is excluded by the new scope, the screen selects the first visible project. Changing the scope itself is file-level state and survives State recreation.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState.build]` When the visible project list is empty, the screen renders the scope filter plus an empty state. Its text is `'내 프로젝트가 없습니다'` in the mine scope and `'프로젝트가 없습니다'` otherwise. The `SectionErrorBanner` remains visible in both the empty and populated layouts, with `onRetry: () => state.retryProjects()`.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState.build]` Tasks are split by exact status equality into requestTasks (`TaskStatus.request`), todoTasks (`TaskStatus.todo`), inProgressTasks (`TaskStatus.inProgress`) and doneTasks (`TaskStatus.done`), and each status-tab label embeds the corresponding list length.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState.build]` When `selectedRoadmapId` is non-null the task list is filtered with `t.roadmapId == selectedRoadmapId`; a null selected roadmap means no filtering. The `'모든 카드'` FilterChip is selected exactly when `selectedRoadmapId == null`, and each roadmap chip is selected when `selectedRoadmapId == r.id`.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState._selectedProjectId]` The project DropdownButton value is resolved by comparing `activeProject.id` against the freshly loaded visible project list and returns null when the active project is absent, so the dropdown cannot hit the "value not in items" assertion after a reload. The dropdown's `onChanged` ignores a null id and selects the project matched by `p.id` (not by name) because duplicate project names are possible.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState.build]` The app-bar bottom height is the fixed scope row (40), optional roadmap row (40), and tab row (48). The `RefreshIndicator` notification predicate accepts only vertical notifications with `n.depth <= 1` so pull-to-refresh still works from inside the `TabBarView`.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState.build]` The floating "new task" button is rendered only for the four status tabs. The milestone, my-tasks, and timeline tabs do not create a task, and the status tab opens `TaskDialog` with that tab's status.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState._confirmDeleteRoadmap]` Roadmap deletion requires the confirmation dialog to return exactly `true`. `state.deleteRoadmap` returning `false` reports failure; a successful delete leaves the associated tasks in place.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState._buildTaskList]` An empty task group renders the text `'카드가 없습니다'` inside a `SingleChildScrollView` with `AlwaysScrollableScrollPhysics` so the refresh path is not lost. The comment counter shown is `task.comments.isNotEmpty ? task.comments.length : task.commentCount`, and the comment section is only rendered when comments is non-empty or `commentCount > 0`. The due date label is produced by `DateFormat('M.d').format(task.dueAt!.toLocal())` and the roadmap chip is constrained to `constraints.maxWidth * 0.4`. The task `ListView.builder` uses bottom padding 96 so the floating action button does not cover the last card. The card title and description are limited to `maxLines: 2` with `TextOverflow.ellipsis`, and the assignee name uses `Flexible` with `maxLines: 1`.
- `[mobile/lib/screens/projects/projects_screen.dart:_ProjectsScreenState._buildTaskList]` A task with a non-null `milestoneName` renders a colored milestone badge below its title.
- `[mobile/lib/screens/projects/project_settings_sheet.dart:_ProjectSettingsSheetState._save]` A blank trimmed project name blocks saving. In create mode the current user is pre-added to `memberIds`; in edit mode the sheet calls `updateProject` with name, description, channel, and archive state and keeps the sheet open on `false`.
- `[mobile/lib/screens/projects/project_settings_sheet.dart:_ProjectSettingsSheetState._save]` The core update API treats a null `channelId` as "unchanged", so the sheet cannot clear an existing channel link; it explains that limitation in the UI instead of sending an ambiguous update.
- `[mobile/lib/screens/projects/project_settings_sheet.dart:_ProjectSettingsSheetState._addMember]` Adding a member to an existing project is applied immediately through `addProjectMember`. If the result is `false`, the optimistic local selection is rolled back and a failure snackbar is shown. Removal follows the same rollback rule.
- `[mobile/lib/screens/projects/project_settings_sheet.dart:_ProjectSettingsSheetState._delete]` Project deletion requires explicit confirmation. The sheet closes only after `deleteProject` returns `true`; a `false` result leaves the sheet open.
- `[mobile/lib/screens/projects/milestone_sheet.dart:_MilestoneDialogState.initState]` A new milestone defaults to now through 14 days later. An edited milestone is prefilled with its local start/end dates, color, progress, and the ids of tasks whose `milestoneId` matches the milestone.
- `[mobile/lib/screens/projects/milestone_sheet.dart:_MilestoneDialogState._save]` A blank title, missing date, or end date before the start date blocks saving. The selected task ids are sent on both create and update; the dialog stays open and reports an error when creation throws or an update returns `false`.
- `[mobile/lib/screens/projects/milestone_sheet.dart:_MilestoneDialogState.build]` When one or more tasks are linked, progress is calculated from the linked tasks' `TaskStatus.done` values and the manual slider is hidden. With no linked tasks, the manual 0-100 percent value is used.
- `[mobile/lib/screens/projects/milestone_sheet.dart:_MilestoneCard._confirmDelete]` Milestone deletion requires exact confirmation. A failed `deleteMilestone` result shows a failure snackbar; the dialog does not close.
- `[mobile/lib/screens/projects/milestone_sheet.dart:milestoneColor]` Six-digit hex colors are parsed as opaque ARGB; other parseable hex lengths are used as supplied. Empty or invalid values fall back to the accent color rather than throwing.
- `[mobile/lib/screens/projects/my_tasks_screen.dart:MyTasksScreen._openTask]` A "my tasks" item from another project selects that project before opening `TaskDetailSheet`, because task mutations operate on the active project's task collection.
- `[mobile/lib/screens/projects/task_detail_sheet.dart:_sendComment]` A comment is submitted only when the trimmed text is non-empty and no submission is in flight; the send IconButton's `onPressed` is null while `_isSubmittingComment` is true. The comment text is captured and `_commentCtrl.clear()` is executed before the await so the controller is never touched after the sheet may have been disposed. After the server call the pending comment is removed only if a comment with the same body exists in `state.activeProjectTasks` for the same task id; on error the pending entry is removed, the text is restored into the controller and a snackbar `'댓글 작성에 실패했습니다: $e'` is shown.
- `[mobile/lib/screens/projects/task_detail_sheet.dart:_deleteComment]` Only comments whose `userId` matches the current user expose a delete button. Deletion has no confirmation step and calls `deleteTaskComment(taskId, commentId)`; a `false` result shows `'의견을 삭제하지 못했습니다'`.
- `[mobile/lib/screens/projects/task_detail_sheet.dart:build]` The displayed task is re-resolved on every build from `state.activeProjectTasks` with `firstWhere((t) => t.id == widget.task.id, orElse: () => widget.task)`, so edits are reflected without closing the sheet. The comment list renders confirmed comments first and pending comments after it, the header count is `task.comments.length + _pendingComments.length`, and the message `'아직 작성된 의견이 없습니다.'` appears only when both lists are empty. The comment list is a shrink-wrapped `ListView.separated` with `NeverScrollableScrollPhysics` so it scrolls only with the outer `SingleChildScrollView`.
- `[mobile/lib/screens/projects/task_detail_sheet.dart:_deleteTask]` Deletion is aborted unless the confirmation dialog returns exactly true, and the sheet is popped only after `state.deleteTask` returned true; a false result shows the snackbar `'할 일을 삭제하지 못했습니다'`.
- `[mobile/lib/screens/projects/task_detail_sheet.dart:_buildStatusDropdown]` The status popup lists every entry of `TaskStatus.values` and displays `s.label`; the status is changed through `state.updateTaskStatus(task, newStatus)` and on failure the status stays unchanged and a snackbar `'상태를 바꾸지 못했습니다'` is shown.
- `[mobile/lib/screens/projects/task_detail_sheet.dart:build]` The due date is rendered with `DateFormat('yyyy.MM.dd')` on `task.dueAt!.toLocal()` and comment timestamps with `DateFormat('MM.dd HH:mm')` on `c.createdAt.toLocal()`. Pending comments are labelled `'전송 중'` and use the current user's name, falling back to the literal `'나'` when `currentUser` is null. The sheet body is wrapped in `AnimatedPadding` with a 180ms `Curves.easeOut` animation driven by `MediaQuery.viewInsetsOf(context).bottom`. The edit IconButton has `constraints: const BoxConstraints(minWidth: 44, minHeight: 44)`.
- `[mobile/lib/screens/projects/task_dialog.dart:initState]` In edit mode the controllers and fields are prefilled from the editing task (title, description, status, assigneeId, roadmapId, milestoneId) and the due date is converted with `editing.dueAt?.toLocal()` because the server supplies a UTC instance.
- `[mobile/lib/screens/projects/task_dialog.dart:_submit]` Submission is blocked when the trimmed title is empty, and the submit button's `onPressed` is null while `_isCreating` is true. In edit mode the description is always passed as a string, because a null argument means "no change" and an empty string is required for the server to clear the description. In edit mode status is never sent because `updateTask` has no status parameter and the detail sheet header's status dropdown owns status changes. In create mode the description is passed as null when empty and the status is passed as `_status`.
- `[mobile/lib/screens/projects/task_dialog.dart:_submit]` Both create and edit pass `milestoneId` to the provider. If `state.updateTask` returns false the dialog stays open with the snackbar `'할 일 수정에 실패했습니다'`; on an exception the snackbar is `'할 일 수정 실패: $e'` or `'할 일 생성 실패: $e'` and `_isCreating` is reset.
- `[mobile/lib/screens/projects/task_dialog.dart:build]` Dropdown current values are restricted to values present in the loaded lists: `selectedAssigneeId` is null unless `_assigneeId` is contained in `memberIds`, `selectedRoadmapId` is null unless `_roadmapId` is contained in `roadmapIds`, and `selectedMilestoneId` is empty unless `_milestoneId` is contained in the active milestone ids. The status dropdown is rendered only when `widget.editing == null`; the assignee dropdown always includes a null-valued `'담당자 없음'` item, and the roadmap dropdown (rendered only when roadmaps is not empty) includes a null-valued `'로드맵 없음'` item. The assignee dropdown label is rendered as `'이름 (직함)'` when the member's user has a non-null title, otherwise just the name.
- `[mobile/lib/screens/projects/task_dialog.dart:build]` The milestone dropdown is rendered only when the active project has milestones. Because the provider treats a null `milestoneId` as "unchanged", choosing `'마일스톤 없음'` for an already linked task is blocked and explained instead of sending an ambiguous update.
- `[mobile/lib/screens/projects/task_dialog.dart:build]` The due date picker is bounded by `firstDate: DateTime.now().subtract(const Duration(days: 30))` and `lastDate: DateTime(2035)`, with `initialDate` = the current `_dueDate` or now + 3 days; the picked date replaces `_dueDate` only when the result is non-null. The due date button label is `'마감일 설정'` when `_dueDate == null`, otherwise `'마감일: ${DateFormat('yyyy.MM.dd').format(_dueDate!)}'`. The dialog is constrained to `BoxConstraints(maxWidth: 480, maxHeight: 600)` and the title field uses `autofocus: widget.editing == null`.

## Side Effects

- `[mobile/lib/screens/projects/projects_screen.dart:initState]` Reads the provider via `context.read<AppState>()` inside `WidgetsBinding.instance.addPostFrameCallback` and conditionally calls `state.loadProjects()` (`GET /workspaces/$workspaceId/projects`).
- `[mobile/lib/screens/projects/projects_screen.dart:build]` Calls `context.watch<AppState>()` so the screen rebuilds on provider changes. The `RefreshIndicator` sets `onRefresh: () => state.loadProjects()` with color `LlackColors.accent`.
- `[mobile/lib/screens/projects/projects_screen.dart:_openProjectSettings]` Opens `ProjectSettingsSheet` with `showModalBottomSheet`; the same sheet is used for a new project and for the active project's overflow-menu "프로젝트 설정" action.
- `[mobile/lib/screens/projects/projects_screen.dart:build]` The project dropdown's `onChanged` calls `state.selectProject(p)` for the project whose id matches the selection. The roadmap FilterChips call `state.filterRoadmap(null)` for `'모든 카드'` and `state.filterRoadmap(r.id)` for each roadmap chip.
- `[mobile/lib/screens/projects/projects_screen.dart:_confirmDeleteRoadmap]` After confirmation, awaits `state.deleteRoadmap(roadmap.id)` (`DELETE /roadmaps/$roadmapId`).
- `[mobile/lib/screens/projects/projects_screen.dart:build]` The floating action button opens `TaskDialog(initialStatus: TaskStatus.values[_tabController.index])`, so a new task inherits the currently visible status column.
- `[mobile/lib/screens/projects/projects_screen.dart:_buildTaskList]` Tapping a card calls `showModalBottomSheet(context: context, isScrollControlled: true, backgroundColor: Colors.transparent)` with builder `TaskDetailSheet(task: task)`.
- `[mobile/lib/screens/projects/project_settings_sheet.dart:_ProjectSettingsSheetState._save]` In create mode awaits `state.createProject(name:, description:, channelId:, memberIds:)` (`POST /workspaces/$workspaceId/projects`); in edit mode awaits `state.updateProject(projectId:, name:, description:, channelId:, isArchived:)` (`PATCH /projects/$projectId`). It pops only after success.
- `[mobile/lib/screens/projects/project_settings_sheet.dart:_ProjectSettingsSheetState._delete]` After confirmation awaits `state.deleteProject(project.id)` (`DELETE /projects/$projectId`).
- `[mobile/lib/screens/projects/project_settings_sheet.dart:_ProjectSettingsSheetState._addMember]` For an existing project awaits `state.addProjectMember(project.id, userId)` (`POST /projects/$projectId/members`).
- `[mobile/lib/screens/projects/project_settings_sheet.dart:_ProjectSettingsSheetState._removeMember]` For an existing project awaits `state.removeProjectMember(project.id, userId)` (`DELETE /projects/$projectId/members/$userId`).
- `[mobile/lib/screens/projects/milestone_sheet.dart:_MilestoneDialogState._save]` In create mode awaits `state.createMilestone(...)` (`POST /projects/$projectId/milestones`); in edit mode awaits `state.updateMilestone(...)` (`PATCH /milestones/$milestoneId`).
- `[mobile/lib/screens/projects/milestone_sheet.dart:_MilestoneCard._confirmDelete]` After confirmation awaits `state.deleteMilestone(milestone.id)` (`DELETE /milestones/$milestoneId`).
- `[mobile/lib/screens/projects/task_detail_sheet.dart:_sendComment]` Awaits `state.addTaskComment(widget.task.id, text)` — `POST /tasks/$taskId/comments` with body `{'body': body}`.
- `[mobile/lib/screens/projects/task_detail_sheet.dart:_deleteComment]` Awaits `state.deleteTaskComment(widget.task.id, comment.id)` — `DELETE /task-comments/$commentId`.
- `[mobile/lib/screens/projects/task_detail_sheet.dart:_openEditDialog]` Opens `showDialog` whose builder returns `TaskDialog(editing: task)`.
- `[mobile/lib/screens/projects/task_detail_sheet.dart:_deleteTask]` Opens a `showDialog<bool>` confirmation `AlertDialog` (`'할 일 삭제'` / `'삭제'` / `'취소'`), then awaits `state.deleteTask(widget.task.id)` — `DELETE /tasks/$taskId` — and finally calls `Navigator.pop(context)`.
- `[mobile/lib/screens/projects/task_detail_sheet.dart:_buildStatusDropdown]` Awaits `state.updateTaskStatus(task, newStatus)` — `PATCH /tasks/$taskId` with a `'status'` body field.
- `[mobile/lib/screens/projects/task_detail_sheet.dart:build]` Calls `context.watch<AppState>()` for the task list and `context.read<AppState>().currentUser` in `_buildPendingCommentRow`. On failure it calls `showAppSnackBar(context, '댓글 작성에 실패했습니다: $e')`; `_deleteTask` shows `'할 일을 삭제하지 못했습니다'` and `_buildStatusDropdown` shows `'상태를 바꾸지 못했습니다'`. The `_commentCtrl` is disposed in `dispose()`.
- `[mobile/lib/screens/projects/task_dialog.dart:_submit]` In edit mode awaits `state.updateTask(taskId: editing.id, title: title, description: desc, assigneeId: _assigneeId, dueAt: _dueDate, roadmapId: _roadmapId, milestoneId: _milestoneId)` — `PATCH /tasks/$taskId` — and in create mode awaits `state.createTask(title: title, description: ..., status: _status, assigneeId: _assigneeId, dueAt: _dueDate, roadmapId: _roadmapId, milestoneId: _milestoneId)` — `POST /projects/$projectId/tasks`. It calls `Navigator.pop(context)` after a successful create/update and `showAppSnackBar(context, ...)` on failure.
- `[mobile/lib/screens/projects/task_dialog.dart:build]` Calls `showDatePicker(context: context, initialDate: ..., firstDate: ..., lastDate: DateTime(2035))` from the due-date `OutlinedButton`. It calls `context.watch<AppState>()` and reads `state.members`, `state.activeRoadmaps`, and `state.activeMilestones` to build the dropdown items. The `_titleCtrl` and `_descCtrl` are disposed in `dispose()`.
